# 모듈 경계

## 독립 개발 단위

| 저장소 이름 | Dart 패키지 이름 | 책임 |
|---|---|---|
| r-edit | r_edit | Flutter Windows 화면·사용자 명령 연결·플랫폼 연동 |
| r-edit-workflow | r_edit_workflow | 작업 데이터, 변경 영향, 계산 요청·결과 수락, 작업자 확인, 저장·출력 흐름 |
| nameplate-text-layout | nameplate_text_layout | 문구 줄바꿈·크기·자폭·위치 계산, 공간 검사, 그룹 선택, 진단 |
| nameplate-dxf-export | nameplate_dxf_export | 확정된 출력 자료의 DXF 표현 |
| r-edit-docs | 해당 없음 | 시스템 전체 요구사항·논리 설계·결정·검증 근거 |

사용자가 원격 저장소를 생성했다고 확인한 것은 r-edit다. 다른 저장소는 해당 작업에 착수할 때 생성한다.
표의 다른 저장소 이름은 개발 기준이며 원격 생성·사용 가능 여부를 조회한 결과가 아니다.
로컬 패키지 폴더는 각각의 Dart 패키지 이름을 사용한다. 하나의 부모 폴더를 공통 Git 저장소로 만들지 않는다.

## 의존 방향

Flutter 앱은 업무 흐름 패키지의 명령을 호출한다.
업무 흐름 패키지가 배치 엔진·DXF 출력의 공개 API를 연결하고 값을 변환한다.
엔진과 DXF 패키지는 앱이나 작업 파일의 저장 형식에 역으로 의존하지 않는다.

엔진 입력에는 문구·형상·영역·적용 규칙·폰트 측정 자료·탐색 조건을 전달한다.
엔진 출력에는 줄별 배치·원문 위치 연결·판정·사유·계산 식별 정보를 담는다.
DXF에는 완료된 배치와 형상, 수량 표현을 반영한 출력 자료를 전달하며 다시 배치하지 않는다.

작업 파일 JSON은 업무 흐름 패키지가 소유한다. 엔진 내부 객체를 그대로 직렬화하지 않는다.
화면과 폰트 측정·파일 선택 등의 플랫폼 연동 경계는 실제 연결 요구에 맞춰 구현한다.
경계 문서는 아직 구현되지 않은 메서드·DTO·필드명을 확정하지 않는다.

## 개발과 배포

독립 패키지는 Flutter UI 없이 개발·검증할 수 있어야 한다.
공개 API가 유지되는 엔진 내부 수정이 앱의 업무 코드 전체 수정으로 번지지 않게 한다.
배포 앱이 사용하는 엔진 버전을 바꾸려면 앱을 다시 빌드·배포한다.
초기에 실행 중 엔진 교체나 동적 플러그인 로딩을 구현하지 않는다.

실제 생성된 패키지를 연결할 때 Git 의존성을 채택한 릴리스 또는 커밋으로 고정한다.
형제 로컬 패키지를 함께 수정할 때는 무시 목록에 둔 pubspec_overrides.yaml을 사용할 수 있다.
앱의 pubspec.lock은 Git으로 관리한다. 현재 선택하지 않은 상태 관리·표·창 관리 라이브러리는 미리 추가하지 않는다.

[기술·SDK·생성·분석·테스트·CI 기준](development-foundation.md)을 현재 기준으로 적용한다.

최소 Provider·라우터·로깅 연결은 업무 엔진·저장 구현을 뜻하지 않는다.
