# nameplate_dxf_export 개발 지침

## 역할
확정된 출력 자료를 DXF로 표현하고 문자·도형·인코딩을 처리. 배치를 다시 계산하거나 작업 파일을 직접 해석하지 않는다. 입력은 확정된 출력 자료이며 인코딩·좌표·형상 지원 범위를 계약에 기록한다.

## 시작
- README와 연결된 문서 저장소의 DECISIONS.md, 현재 작업 계약을 읽는다.
- 사용자 최신 지시를 우선한다. 예전 단일 저장소 계획과 미완료 편집 저장을 현재 요구로 적용하지 않는다.
- 실제 SDK 버전과 이 저장소의 현재 의존성을 먼저 확인한다.

## 구현
- 요청한 작은 완료 단위를 구현하고 기존 동작에 미치는 영향을 확인한다.
- 코드 이름은 업무 대상·동작·단위가 드러나게 한다. 줄바꿈 방식은 자동/직접 지정으로 구분한다.
- 원문 공백·기호·대소문자를 임의로 정규화하지 않는다. 제품·영역은 이름이나 문구가 아닌 식별 정보로 연결한다.
- 문구 배치 조건과 수량·출력 표현을 구분한다. 정상 판정과 작업자 확인을 구분한다.
- 공개 API로 패키지를 사용하고 다른 패키지의 내부 src 경로를 가져오지 않는다.
- API나 저장 형식의 의미가 바뀌면 영향과 이관 필요성을 먼저 설명한다. 구현상의 선호로 기존 형식을 조용히 바꾸지 않는다.
- 실제 필요한 의존성만 추가한다. 일반화된 플러그인 프레임워크나 대형 공용 패키지를 선행 구축하지 않는다.
- 합성 예제와 기존 시험 결과를 제품의 실제 검증 결과로 표현하지 않는다.

## 확인
```text
dart pub get
dart analyze
dart test
```
명령이 실행되지 않으면 실행하지 못한 이유를 기록한다. 테스트를 실행한 것으로 꾸미지 않는다.
실제 의미 있는 동작을 확인하고 변경이 없는 기능의 시험을 불필요하게 확장하지 않는다.

## 마무리
변경 내용·공개 계약 영향·실제 확인 결과·남은 한계를 보고한다.
README와 docs/contract.md는 실제 기능에 맞춰 유지하고, docs/next-step.md에 다음 한 가지 작업을 남긴다.
기준 문서의 경로와 채택한 문서 저장소 커밋을 README에 기록한다.
