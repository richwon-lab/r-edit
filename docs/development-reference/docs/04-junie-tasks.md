# Junie 작업 지시

새 프로젝트에서 시작한다. 아래 작업을 한 번에 모두 수행하지 않고 한 작업의 변경과 확인을 마친 뒤 다음으로 넘어간다.
기준 자료는 이 문서 저장소의 DECISIONS.md와 논리 설계다. 이 문서의 경로는 코드 저장소의 README에 연결한다.

## 작업 1 프로젝트 생성과 기준 문서 연결

다음 내용을 Junie에 전달한다.

> 새 순수 Dart 패키지 `r_edit_workflow`의 초기 구조를 준비해줘.
> 아직 생성하지 않았다면 현재 위치를 먼저 확인하고 `dart create -t package r_edit_workflow`로 새 폴더를 만들어줘. 이미 생성된 패키지라면 그 프로젝트를 사용해줘.
> 이 패키지는 도안 작업 모델·입력 변경·배치 결과 확인·저장 정책·JSON 입출력을 담당해.
> Flutter UI와 배치 알고리즘, DXF 작성은 각각 별도 프로젝트에서 개발할 거야.
> 내가 제공한 AGENTS.md와 현재 결정 사항을 읽고 README에 역할과 지원 범위를 기록해줘.
> `publish_to: none`, 공개 진입점, 내부 구현 위치, 시험 위치를 정리해줘.
> 아직 작성하지 않은 기능을 완료했다고 기록하지 말고, 설치된 Dart SDK 버전을 기록해줘.
> `dart pub get`, `dart analyze`, 시작 시험을 실행해서 초기 상태를 확인해줘.
> 마지막에 실제 변경 파일·실행 결과·다음 한 가지 작업을 알려줘. 원격 저장소 생성과 push는 이번 작업에 포함하지 마.

이 작업의 완료 기준은 프로젝트가 열리고 자체 분석·시작 시험이 실행되는 것이다. 생성 템플릿 시험 통과는 제품 기능 검증이 아니다.

## 작업 2 모델과 JSON 왕복

> 현재 결정과 논리 설계를 기준으로 도안 작업의 최소 모델과 JSON 입출력을 구현해줘.
> 작업 파일, 제품 항목, 적용 도안, 영역별 문구, 제품별 완료 배치와 확인, 출력 설정, 파일 연결을 담아줘.
> 코드 이름은 네이밍 기준을 참고하되 역할에 맞춰 제안하고, 원문·줄바꿈 방식·판정·확인을 섞지 마.
> 두 제품이 같은 적용 도안을 공유하는 합성 예제를 작성해줘. 한 제품은 자동 줄바꿈 정상 결과, 다른 제품은 직접 지정 결과와 작업자 확인을 갖도록 해줘.
> 예제 결과는 모델 시험용임을 밝히고 실제 계산 엔진이 산출한 것으로 표시하지 마.
> 앞뒤·연속 공백, 여러 영역, 같은 원문이 반복되는 별도 제품, 직접 지정 한 줄을 보존해줘.
> 저장 형식 버전과 계산 엔진 식별 정보를 구분하고, 알 수 없는 필수 형식을 임의 기본값으로 보정하지 마.
> 직렬화 전후 원문·연결·줄 구성·결과·판정·사유·확인이 같은지 시험해줘.
> 아직 Flutter 화면·엔진 구현·GitHub 자동화는 추가하지 말고 변경과 실제 확인 결과를 알려줘.

문자 위치와 경계의 단위가 필요해지는 시점에 결정하고 README 또는 계약 문서에 명시한다. 영어 샘플만 통과한 것으로 Unicode 전체가 처리됐다고 기록하지 않는다.

## 작업 3 수정과 저장 정책

> 현재 모델 위에 작업 세션과 저장 조건을 구현해줘.
> 문구·도안·배치 관련 조건을 바꾸면 영향받는 결과를 현재 결과로 쓰지 못하게 하고 해당 작업자 확인도 무효화해줘.
> 수량·순서만 바꾸면 배치와 확인을 유지해줘. 원래 판정은 확인 후에도 바꾸지 마.
> 전체 제품에 현재 입력과 맞는 배치가 있고 정상 또는 작업자 확인 조건을 만족할 때만 저장할 자료를 만들 수 있게 해줘.
> 저장 가능 여부는 계산해서 판단하고 저장 파일에 중복 상태값을 두지 마.
> 미완료 입력·계산 작업 식별·진행 상태는 메모리에서만 관리해줘.
> 배치 엔진이 아직 없으므로 시험 대역으로 결과 수락 계약을 검증하고 실제 엔진 구현으로 표시하지 마.

## 작업 4 디스크 저장

> 검증된 저장 자료를 UTF-8 JSON으로 디스크에 쓰고 다시 읽는 기능을 구현해줘.
> 기존 파일을 직접 덮어쓰며 쓰기보다 같은 위치의 임시 파일에 완성한 뒤 교체하는 절차를 사용해줘.
> 쓰기 실패·교체 실패 시 이전 파일을 보존하는 동작을 Windows에서 검증해줘.
> 이 확인을 전원 차단·Drive 동기화 완료까지 보장하는 시험으로 표현하지 마.

여기까지가 첫 작은 완료 단위다. 실제 엔진 이식은 그다음에 별도 `nameplate_text_layout` 프로젝트에서 진행한다.
그때 기존 시험 코드와 폰트 측정 자료를 가져와 공개 입력·결과 계약을 정하고 시험 사례를 선별한다.
