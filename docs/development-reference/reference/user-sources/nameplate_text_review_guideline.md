# 명판 문구 검수 가이드 (줄바꿈 제안 + 의심 항목 표시)

> 목적: 고객이 제공한 문구를 **그대로 유지**한 상태에서, 명판 레이아웃에 맞는 **줄바꿈(개행) 배치안**을 제안하고, **오타/표기 불일치로 의심되는 항목을 ‘확인 필요’로 표시**한다.  
> 원칙: 문구의 **모든 문자/특수문자/띄어쓰기/대소문자/구두점**은 **절대 임의 수정하지 않는다.**  
> 사용: 내가 “문구 검토해줘”라고만 말해도, 아래 **필수 확인 질문**을 먼저 확인한 뒤 검토를 진행한다.

---

## 0) 작업 전 필수 확인 질문 (요청마다 무조건 재확인 / 기본값 없음)

아래 항목은 **기본값이 없다.** 요청마다 달라지므로 **반드시 재확인**한다.

1) **고객사(회사명 / 프로젝트명)**  
- 고객사별 표기 습관/표준(약어, 공백, 기호)을 그대로 반영하기 위함

2) **명판 레이아웃 조건(핵심)**  
- 실사용 가능한 **텍스트 영역 폭/높이(mm)**  
- **최대 줄 수**(1~4줄 등, 작업마다 다름)   
- 한 줄에 넣을 수 있는 **실제 글자량/폭 기준**(회사 내부 경험치가 있으면 그 기준)

> 위 2개가 확정되지 않으면 줄바꿈을 “확정안”으로 만들 수 없다.  
> **질문 → 조건 확정 → 검토** 순서로 진행한다.

---

## 1) 검토 범위 기본값

- **문구 내용 수정: 금지(기본값)**  
  - 누가 봐도 오타처럼 보여도 **즉시 수정/정정하지 않는다.**  
  - 대신 **‘확인 필요(고객 확인)’** 로만 표시한다.

- **허용되는 변경: 개행(줄바꿈)만**  
  - 문자 순서, 공백, 기호는 그대로 두고 **줄만 나눈다.**

- **원문 순서 유지: 기본값**  
  - 사용자가 준 목록 순서를 유지한다.

---

## 2) 추가로 확인하면 좋은 항목 (상황에 따라 재질문)

- **세트 문구 통일 필요 여부**  
  - 유사 문구(예: 전압/번호/장비 계열)가 같은 장소에 붙는지  
  - 길이와 무관하게 **같은 줄 패턴**으로 맞출지

- **문구 그룹(카테고리) 존재 여부**  
  - 예: `NO.1/NO.2`, `M/E`, `G/E`, `ICMS`, `BMS` 등  
  - 그룹이 있으면, 그룹별로 줄바꿈 패턴을 통일하는 쪽이 깔끔하다.

---

## 3) 줄바꿈 제안 규칙 (권장 / 단, 고객사·현장 조건이 우선)

> 아래 규칙은 “보기/가독성/통일감”을 위한 권장안이며, **반드시 0) 레이아웃 조건을 먼저 확정**한 뒤 적용한다.  
> 어디까지나 **문구를 바꾸지 않고 ‘개행 위치’만 선택**한다.

### 3-1) 세트 통일감 우선
- 같은 계열 문구는 길이가 달라도 **같은 줄 패턴**을 우선 고려한다.  
  - 예: `DC24V↵RECEPTACLE` / `AC220V↵RECEPTACLE`

### 3-2) 카테고리 태그는 공간이 허용하는 만큼 앞줄에 묶기
- `M/E`, `G/E`, `ICMS` 같은 태그는  
  - 공간이 넉넉하면 “태그를 머리말처럼” 보이게 배치할 수 있고  
  - 공간이 협소하면 **태그를 단독 줄로 빼지 말고 뒤 토큰과 묶어** “세부 카테고리”처럼 보이게 할 수 있다.  
  - 예: `M/E OMD↵DISPLAY UNIT`

### 3-3) 괄호 조건은 마지막 줄 단독이 깔끔한 편
- 예: `SWITCH FOR MONITOR↵CEILING LIGHT↵(NORMAL)`

### 3-4) 의미 단위로 끊기
- 끊는 기준은 “읽는 덩어리”다.  
- 단, 문구 수정은 금지이므로 **단어/기호/공백을 바꾸지 않고 개행만 조정**한다.
- 너무 긴 경우 하이픈(-)이나 슬래쉬(/) 같은 부분에서도 줄바꿈 할 수 있다.
---

## 4) 오타·표기 불일치 검수는 “수정”이 아니라 “표시”만 한다

### 4-1) 아래 내용은 빈번함으로 확인도 생략해도 된다. 
- 공백/표기 혼재: `DC24V` vs `DC 24V`  
- 약어/구두점 혼재: `PRESS.` / `PRESS` / `IND.` 등  
- 중복 단어로 의심: `... BOILER BOILER ...`  
- 해석이 애매한 약어/축약: 의미 확신이 없으면 “확인 필요” 처리

### 4-2) 기본적으로 하지 않는 것
- 오타로 보인다고 **바로 고쳐서 결과에 반영**
- 띄어쓰기/기호를 “더 예쁘게” 다듬기
- 고객 표준을 모르는 상태에서 표준화 단정

---

## 5) 결과 출력 형식(검토 답변 표준)

요청을 받으면 아래 순서로 답변한다.

1) **필수 확인 질문(0번 2개)**  
2) 원문 순서대로 **줄바꿈 적용 결과**(조건의 최대 줄 수 준수)  
3) **확인 필요 리스트(고객 확인용)**  
   - 항목: 원문 그대로 + 왜 의심인지 한 줄 메모  
   - 절대 “수정본”을 본문에 섞지 않는다.
