문서 ID RW-REQ-001  |  버전 0.7  |  갱신일 2026년 10월 3일

문서 상태: 요구사항 개정 초안. 배치 기준 조율 시안은 초안으로 채택했다. 세부 UI와 제품 구현 완료를 승인한 것은 아니다.

이 문서는 개발 담당자와 현업 검토자가 무엇을 해결하고 어떤 결과를 확인할지 합의하기 위한 기준이다. 첫 개발 대상은 명판 도안 자동화이며, 검색과 업무 지원은 자동화에서 쌓이는 정보를 바탕으로 확장한다. 기술과 화면 구조를 먼저 확정하지 않는다.

성공 기준

소량 주문에서도 직원이 기존 수작업보다 이 프로그램을 먼저 선택하고 싶도록 준비·수정 부담을 줄이는 것이 핵심 목표다. 주요 지표는 전체 작업 시간과 개별 수정량이다. 자동 생성 속도가 빨라도 직원이 대부분의 명판을 다시 손봐야 한다면 핵심 목표를 충족하지 못한다. 원문 보존과 과거 디자인의 일관성을 함께 확인한다.

현재 작업시간·수정 비율·재작업 비용의 정량 기준은 미측정이다. 개선율이나 처리 속도 목표를 임의로 확정하지 않고 대표 작업을 비교해 정한다.

읽는 순서

이번 개발은 26절 범위와 27절 완료 기준부터 확인한다. 23~25절은 최근 합의한 기능과 조율 초안, 28절은 구현 상태다. 도형 역할과 DXF 지정 절차는 29~30절에서 보완한다.

문서에서 사용하는 상태

합의: 사용자가 명시하거나 수용한 요구. 초안 채택: 기능과 흐름의 출발안으로 사용하며 실제 사용 뒤 개선. 제안: 구체적인 구현·완료 기준의 검토안. 보류: 후속 연구·연동 조사 대상. 구현 상태는 별도 기록하며 요구사항 합의를 검증 통과로 취급하지 않는다.

용어 구분

디자인 작성은 외형·홀·장식·텍스트 영역·기본 스타일을 정하는 작업이다. 문구 자동 배치는 정해진 디자인에 문구를 넣는 작업이다. 홀이나 텍스트 영역을 변경하면 다른 디자인으로 취급한다. 처음 넣는 문구 묶음을 신규 디자인이라고 부르지 않는다. 프로그램에서 내보낸 배치와 Type3 수정 후 최종 도안도 구분한다.

3 현재 업무와 목표 흐름

확인된 현재 업무

발주는 메일·전화·사진·팩스·Excel·CAD 등 다양한 형태로 들어온다. 도안자가 내용을 해석하고 부족한 조건은 고객에게 확인한다. 현재는 대량의 동일 형태 명판에 자동 생성 프로그램을 사용할 때만 문구를 Excel로 정리한다. 그 외에는 발주서를 보며 직접 도안을 작성하고 문구를 복사·붙여넣거나 타이핑한다.

Excel은 한 행에 한 항목, 각 열에 메인 문구·번호·전압 같은 텍스트를 넣는 형태다. 기존 R-EDIT은 문구 배치와 격자 생성을 수행하지만 줄바꿈·자폭 조정이 남는다. 수량 기능이 없어 행 복사 또는 Type3 복제를 혼용한다.

발주 확인 후 작업지시서를 먼저 작성하고 분배한다. 파일 목록은 도안 작업 중 채운다. 한 발주에 여러 디자인이 있으며 같은 디자인별로 문구를 준비하고 생성한다. 정상적으로는 발주의 도안을 모두 끝낸 후 생산에 넘긴다. 급한 일부 선행 생산은 드문 예외로 수동 대응한다.

보존해야 하는 정보

발주 아래 선택적 프로젝트와 디자인별 작업·생산 항목을 연결한다. 외형·홀·테두리·장식과 그 역할·배치 제약·텍스트 영역, 원문·수량, 자재·두께·색상·가공 방식, 기본 커터, 고객사·선택적 내부 구분, 적용 기준과 값, 실제 줄바꿈·크기·줄별 자폭·위치, 출력 이력·최종 파일을 보존한다. 생성 조건만으로 과거 결과의 재현을 보장하지 않는다.

작업 중 변경은 저장하되 다른 작업의 참고 기준으로 확정하지 않는다. DXF 내보내기 시 작업자의 수정까지 반영된 배치를 기록한다. 공통 디자인 등록은 별도 의도이며 일회성 작업에도 깊은 등록 절차를 요구하지 않는다.

운영 전제

공용 서버 PC는 현재 없다. 같은 Google Drive 계정을 파일 공유에 사용한다. 평상시 3명이 다른 주문을 병행하고, 드물게 작업을 이어받는다. 외부 프로그램과 탐색기를 통한 기존 업무도 계속 가능해야 한다.

4 디자인 작성과 편집 요구사항

R01 새 디자인 작성과 DXF 가져오기

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01

프로그램에서 일반적인 2D 명판 디자인을 직접 만들고 고객 DXF를 가져와 편집한다. 외형·홀·테두리·장식 도형·복수 텍스트 영역을 초기 범위에 포함한다. 복잡한 정보성 표 전체를 작성하는 범용 CAD 수준의 기능은 후속 검토한다.

확인 기준: 직접 작성과 DXF 가져오기 두 경로에서 외형·홀·테두리·장식·텍스트 영역을 수정하고 생성 단계로 진행한다. 지원 객체·DXF 버전은 별도 검증한다.

R02 객체의 업무상 역할 지정

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

객체에 외곽·홀·테두리·장식 등의 역할을 사람이 지정한다. 형상만으로 확정하지 않으며 여러 객체를 묶어 지정할 수 있어야 한다. 용도와 배치 제약·출력 포함 여부는 구분한다. 구체적 처리 초안은 29~30절에 정리한다.

확인 기준: 같은 원 형상 두 개에 서로 다른 역할을 지정할 수 있고, 배치 시 지정한 역할에 맞는 조건이 적용된다.

R03 외곽과 내부 객체의 독립 수정

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01

외곽의 가로·세로, 홀 위치·크기, 테두리의 크기·위치를 각각 바꿀 수 있어야 한다. 외곽만 확대하고 테두리를 유지하는 작업도 가능해야 한다.

확인 기준: 외곽 확대·테두리 축소·홀 이동 사례에서 선택하지 않은 객체가 의도 없이 변하지 않는다. 크기 변경 시 다른 객체의 추종 방식은 고정하지 않는다.

R04 여러 텍스트 영역 구성

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

사용자가 텍스트 영역을 자유롭게 추가하고 이름·위치·크기·정렬·폰트·기본 글자 크기를 정한다. 타이틀·서브 타이틀·NO·RAT는 사용 예이며 고정된 명판 유형이나 영역 역할 목록이 아니다. 각 영역은 여러 줄을 지원한다.

확인 기준: 하나의 명판에서 각 영역에 별도 문구와 스타일을 연결한다. 기본 글자 크기는 사람이 정하며 반복 생성마다 관리자 승인을 요구하지 않는다.

R05 직접 조정과 반복 사용 지원

상태: 제안  |  우선순위: 핵심  |  관련 문제: P01

고객별로 다른 크기 변경 방식에 대응해야 한다. 한 번의 직접 편집과 재사용할 위치 관계 설정을 구분하는 안을 검토한다. 모든 객체에 관계 설정을 강제하지 않는다.

확인 기준: 외곽만 변경하는 경우와 홀의 가장자리 거리를 유지하는 경우를 각각 표현할 수 있는지 확인한다. 세부 편집 기능과 관계 설정 방식은 미정이다.

5 문구 입력과 배치 요구사항

R06 표와 도안의 동시 편집

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P04

한 행은 명판 항목 하나, 여러 문구 열은 해당 명판의 여러 텍스트 영역에 대응한다. Excel과 유사한 셀 선택·직접 입력·표 붙여넣기를 지원한다. 표와 미리보기를 함께 보거나 미리보기만 보며 문구를 편집할 수 있어야 한다. 재배치는 명시적인 버튼으로 실행한다.

확인 기준: 선택한 셀의 명판·영역을 미리보기에서 식별하고 반대로 선택·편집할 수 있다. 영역 이름을 열 머리글로 연결하고 불명확한 열 대응은 확인한다. 문구 수정만으로 줄바꿈이 계속 변하지 않으며 미반영 결과를 구분한다. 상세 붙여넣기 조작은 Excel 관행을 따른다.

R07 빈 명판 대응과 원문 보존

상태: 합의  |  우선순위: 핵심  |  관련 문제: P04

예비용으로 문구가 전혀 없는 명판도 생성할 수 있어야 한다. 빈 문구를 일률적으로 생성 차단하지 않는다. 문구의 문자·기호·띄어쓰기·대소문자를 임의로 고치거나 누락하지 않는다.

확인 기준: 정상 문구·일부 빈 영역·전체 빈 명판을 구분해 시험한다. 의도 미확인 빈칸에는 경고, 의도적 빈 명판에는 허용 표시를 두는 안은 제안이다. 입력한 글자의 생성 중 누락은 프로그램 오류로 취급한다.

R08 수량을 반영한 생성

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P04

항목별 수량을 관리한다. 필요한 개수만큼 도안을 복제하거나, 항목별 도안 하나와 수량을 표시하는 두 출력을 지원한다. 반복 행을 임의로 제거하지 않는다.

확인 기준: A·B·C 수량 1·10·1, 다른 디자인의 D·E·F 각 2개는 6종 18개다. 두 출력에서 총수량과 대상 연결이 같아야 한다. 기본값과 출력 방식 선택 단위는 미정이다.

R09 유사 문구의 일관된 배치

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

공통 패턴 기준을 적용한 고객사에서 과거 기록과 이번 문구를 함께 탐색한다. 필요하면 팀·사업장 등으로 구분하되 프로젝트 차이만으로 차단하지 않는다. 머리말·꼬리말·중간 구절과 번호를 고려하며 가공·가독성·디자인 선호보다 패턴을 무조건 우선하지 않는다. 전 고객에 강제하지 않는다.

확인 기준: 번호 계열·공통 꼬리말·중간 구절을 나란히 비교한다. 단어 하나의 우연한 일치로 관련성을 단정하지 않는다. 다른 프로젝트의 기록을 활용하고, 다른 내부 구분의 전용 기준은 자동 전파하지 않는다. 동일 디자인의 과거 확정 배치는 새 문구 때문에 바뀌지 않는다.

R10 기본 스타일을 기준으로 자동 조정

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

기본 글자 크기는 사람이 정한다. 한 텍스트 영역 안에서는 모든 줄의 글자 크기를 같게 유지하고 자폭은 줄마다 조정하는 것을 공통 기본 원칙으로 한다. 자간·줄 간격은 일반적으로 유지한다. 필요하면 해당 영역 전체의 글자 크기를 함께 줄인다. 타이틀의 자간과 글자 크기 확대는 연구 후 정한다.

확인 기준: 한 영역 내 줄별 글자 크기는 같고 자폭은 다를 수 있다. 같은 줄의 크기·자폭도 기본적으로 같다. 혼합 문자·폰트의 보정 예외는 보류한다. 자간·줄 간격과 타이틀 확대 방식은 임의로 확정하지 않는다. 인쇄에는 조각 커터 조건을 적용하지 않는다.

6 배치 품질과 확인 요구사항

R11 배치 후보 평가와 실패 표시

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

줄바꿈·자폭·허용된 크기 조정의 조합을 평가한다. 글자가 온전히 들어가고 가공 후 읽을 수 있는지를 우선한다. 미관상 선호는 연속 감점으로 비교하며 영역 이탈·홀 및 지정한 도형의 금지 영역 침범은 정상 결과에서 제외한다. 적합한 후보가 없으면 실패와 개선용 후보를 표시한다.

확인 기준: 물리적 위반을 점수로 상쇄하지 않는다. 가공 경험의 참고값을 정확한 물리 한계로 단정하지 않는다. 평균 점수로 심한 개별 문제를 숨기지 않으며, 가공 확인이 필요한 예외는 자동 완료하지 않는다. 수치·가중치는 연구한다.

R12 특이 문구를 이용한 디자인 점검

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

디자인의 배치 기준을 처음 조율할 때 실제 문구와 짧은·긴 문구, 긴 단어의 앞·중간·끝 배치, 여러 영역, 유사 문구 묶음, 기존 채택 결과를 함께 비교한다. 시험 문구 자동 보충과 결과별 판단 기록을 지원하는 초안은 25절을 따른다.

확인 기준: 실제 입력 외 시험용 문구로 홀·여백·줄바꿈 동작을 점검한다. 시험용 문구와 실제 주문 문구를 구분하며, 시험 결과를 실제 수량에 포함하지 않는다.

R13 오타 의심과 표기 확인 지원

상태: 합의  |  우선순위: 핵심  |  관련 문제: P03 P04

의심 항목과 명확한 문제의 알림 수준을 구분하고 해당 문구를 빠르게 확인·수정할 수 있어야 한다. 고객사·프로젝트 단위의 사용자 사전으로 지정 용어와 업종 약어를 관리한다. 이번만 무시와 사전 추가를 구분한다.

확인 기준: 고객사·프로젝트의 용어를 해당 범위에 적용하고 다른 고객에 무조건 전파하지 않는다. 의심 문구는 원문을 유지한다. 사전 공유·변경에 따른 다른 작업자 영향은 권한 원칙을 따른다.

R14 개별 및 묶음 수정

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

프로그램 내부에서는 여러 줄을 하나의 텍스트 영역으로 편집한다. 생성 후 특정 명판·영역 또는 관련 묶음의 문구·줄바꿈·자폭을 직접 수정할 수 있어야 한다. 오타 검수와 배치를 마친 뒤 DXF로 내보내며, 이번 수정이 공통 기준을 자동으로 바꾸지 않게 한다.

확인 기준: 긴 문구 한 줄의 자폭만 바꾸는 사례와 묶음 전체의 줄바꿈을 바꾸는 사례를 구분한다. 선택하지 않은 대상과 다른 직원의 기준은 그대로 유지된다.

R15 재생성 선택과 결과 보존

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

수동 수정의 유지 여부를 선택하고, 다시 생성하기 전 결과를 잃지 않으며, 대안을 비교해 채택할 수 있어야 한다. 레이어·결과 버전 등 구체적인 표현 방식은 보류한다.

확인 기준: 수동 수정 유지와 자동 재시도를 각각 시험하고 이전 결과로 돌아갈 수 있다. 문구 변경 시 영향받는 배치를 확인한다. 홀·텍스트 영역 변경은 다른 디자인의 작업으로 분리하며 동일 디자인 재주문의 예외로 처리하지 않는다.

7 출력과 재사용 요구사항

R16 편집 가능한 텍스트 출력

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

DXF는 편집 가능한 줄별 TEXT로 출력하며 글자를 윤곽선으로 변환하지 않는다. 기본 출력은 R2000이다. 검증한 문구 유니코드 이스케이프 처리와 글꼴명 처리를 구분하고, 계산한 위치를 명시하여 Type3의 MTEXT 정렬 해석에 의존하지 않는다.

확인 기준: R2000·R2004 문구 표시와 후속 중앙 정렬·폰트 표시가 정상이라는 사용자 관찰이 있다. 글꼴명까지 일괄 유니코드 이스케이프하는 방식은 사용하지 않는다. 줄별 객체 분리는 수용한다. 전체 문자·폰트·편집·정밀 치수·실제 가공까지 검증한 것은 아니다.

R17 과거 기준 유지와 선택적 개선

상태: 합의  |  우선순위: 핵심  |  관련 문제: P02

동일한 적용 범위에서 같은 디자인·같은 문구를 재주문하면 프로그램에서 내보낸 과거 채택 배치를 우선 재사용한다. 새 문구는 과거 패턴을 참고하여 배치한다. 오류 수정 등 개선 기준을 명시적으로 적용할 수 있지만 프로그램 업데이트가 과거 결과를 조용히 바꾸면 안 된다.

확인 기준: 동일 문구는 저장된 배치 자체를 재사용한다. 새 문구 추가로 과거 배치를 재계산하지 않는다. 홀·텍스트 영역이 바뀌면 다른 디자인이다. 별개 주문의 배치가 충돌할 때는 이어받은 기록·내부 구분·명시적 대체 관계를 확인하며, 해결되지 않으면 확인 대상으로 남긴다.

R18 작업 기록과 공통 디자인 등록

상태: 합의  |  우선순위: 핵심  |  관련 문제: P02 P03 P05

작업 중 내용은 자동 저장하고 DXF 내보내기 시 수정된 문구와 배치를 채택 기록으로 남긴다. 같은 작업의 재출력은 이전 이력을 보존하면서 해당 작업의 재사용 기준을 갱신한다. 공통 디자인 등록은 별도이며 허용 범위 안의 새 디자인은 도안자가 관리자 승인 없이 등록할 수 있다.

확인 기준: 별도 등록 없이 일회성 작업 기록이 남는다. 내보내지 않은 수정은 다음 주문에 적용하지 않는다. 재출력해도 다른 주문·고객사 공통 기준은 자동 변경되지 않는다. 재사용 디자인에는 고객사·선택적 내부 구분·태그·선택적 프로젝트·치수·홀을 연결한다.

R19 기준 변경의 영향 범위와 승인

상태: 합의  |  우선순위: 핵심  |  관련 문제: P02 P03

관리자는 핵심 배치 방식과 허용 범위를 승인한다. 여러 배치 방식이 가능하며 도안자는 허용 범위에서 고객·프로젝트·이번 작업을 조정한다. 누구나 개선안을 제출할 수 있다. 범위 밖 예외와 다른 직원에게 영향을 주는 기존 공통 기준 변경은 관리자 최종 승인을 거친다.

확인 기준: 새 디자인 등록과 기존 공통 기준 변경을 구분한다. 정상 작업마다 관리자 확인을 요구하지 않으며, 개인 조정이 다른 직원의 작업에 즉시 전파되지 않는다.

R20 최종 파일 연결과 한계 표시

상태: 합의  |  우선순위: 핵심  |  관련 문제: P02 P05

프로그램에서 내보낸 배치와 Type3 수정 후 실제 완료 도안을 구분하고 최종 VND·EPS 등을 연결한다. Type3 수정 내용을 추적·역반영하지 않는다. 연결 파일은 사람이 참고하며 자동 배치의 기준 데이터는 프로그램 안의 채택 기록으로 한정한다.

확인 기준: 조회·재사용 시 “프로그램에서 내보낸 배치이며 실제 완료 도안과 다를 수 있음”을 알 수 있다. 연결 파일이 있다고 실제 납품 배치와 동일하다고 판정하지 않는다.

11 평가 시각화와 이전 변경 내역

R21 연속 점수와 공간 분포의 시각화

상태: 제안  |  우선순위: 핵심  |  관련 문제: P01 P02

관리자가 여백 등 공간 관련 평가 기준을 조정할 때 명판 위에 점수 분포를 색상으로 표시하여 영향을 이해할 수 있게 하는 안을 검토한다. 색상 범례와 값의 의미를 함께 보여준다.

확인 기준: 여백 기준과 가중치를 바꿨을 때 변화가 설명 가능해야 한다. 위치별 색상이 전체 도안의 종합 점수나 품질 보증을 뜻하지 않도록 구분한다. 상세 표현과 계산 방식은 연구 대상이다.

평가 시각화에서 구분할 것

선호하는 여백의 범위와 그 범위를 벗어났을 때의 감점 강도는 서로 다른 설정이다. 여백 비율의 기준이 가로·세로·텍스트 영역 중 무엇인지 정의해야 한다. 연속 색상은 공간 평가에 사용하고, 줄바꿈의 의미·유사 문구 일관성은 별도의 설명과 실제 배치 비교로 확인한다.

첨부한 색상 분포 이미지는 표현 방식의 참고다. 물리적 열 분포를 명판 디자인의 평가 함수로 전용하지 않는다. 홀 주변 금지 영역은 점수 분포와 구별해 표시하는 안을 검토한다.

12 자동 배치의 판단 원칙

R22 작업자와 무관한 일관된 자동 결과

상태: 합의  |  우선순위: 핵심  |  관련 문제: P01 P02

일반 작업에서는 프로그램이 가장 적합한 결과 하나를 정한다. 작업자가 여러 미관 후보 중 하나를 매번 선택하는 흐름을 기본으로 삼지 않는다. 동일한 디자인·문구 묶음·적용 기준·과거 기록·폰트 환경에서는 작업자가 달라도 같은 결과가 나와야 한다.

확인 기준 제안: 입력 행 순서를 바꾸거나 수량만 변경해도 문구의 줄바꿈과 스타일은 유지한다. 문구 집합 자체가 바뀌는 경우와 이미 생산된 과거 결과를 유지하는 경우는 구분해서 시험한다. 연구·기준 조정과 예외 수정에서는 후보 비교를 허용한다.

공통 구조와 과거 결과를 함께 고려

공통 패턴은 머리말·꼬리말·중간 구절과 번호 등 가변 부분을 모두 단서로 삼는다. 고객사를 기본 범위로 과거 기록을 참고하며 필요하면 내부 구분을 사용한다. 최신 시험은 공통 연속 구간까지 확장했지만 복잡한 의미 관계와 겹치는 패턴 전체를 해결한 것은 아니다.

동일 디자인·동일 문구 재주문은 프로그램에서 내보낸 채택 배치를 우선 재사용한다. 추가 문구만 과거 구조와 스타일을 참고하여 새로 배치한다. 과거 기록을 조용히 바꾸지 않는다. VND 소급 분석과 Type3 최종 수정 추적은 하지 않는다.

디자인 조건과 배치 결과의 경계

배치 단계에서는 외형·홀·장식·텍스트 영역·기본 글자 크기와 정렬이 정해져 있다. 외형이나 홀을 자동 배치가 임의로 옮기지 않는다. 홀·텍스트 영역 변경은 다른 디자인을 작성하는 작업이며 동일 디자인의 재주문 처리에 포함하지 않는다.

중앙 중심 정렬이면 실제 여러 줄 텍스트 묶음의 중심을 기준으로 배치한다. 공통 첫 줄이 있다는 이유로 서로 다른 줄 수의 첫 줄 높이를 고정하지 않는다. 자간·줄 간격은 기본적으로 유지하며 타이틀의 짧은 문구 확대와 자간 조절은 연구 후 정한다.

점수와 통과 조건의 구분

여백·자폭·크기·선호 줄 수는 적정 범위에서 멀어질수록 감점하는 방향으로 연구한다. 줄바꿈 위치와 줄 수는 이산적인 선택이므로 점수가 연속적이어도 결과가 항상 조금씩만 변하는 것은 아니다. 문구 보존과 물리적 금지 영역은 별도 통과 조건으로 검사한다.

우선 글자가 가려지지 않고 가공·판독 가능해야 한다. 이번 MRCE 디자인에서는 가공 조건을 유지하는 범위에서 3줄을 우선하고, 공통 구절 보존은 그다음에 고려한다. 3줄을 지키느라 과도하게 축소해야 한다면 4줄도 비교한다. 이 상대 순서를 다른 디자인에 그대로 강제하지 않는다.

제공 폰트·형상 배치 실험과 Type3 전체 문구 유니코드 표시 시험을 진행했다. 사용자에게 두 DXF 버전이 정상 표시됐으나 글자 크기 표시·정밀 치수·실제 조각의 정량 대응까지 검증한 것은 아니다. 홀 머리·여유·점수는 시험값이다.

업무 효과 측정

소량은 현재 수작업, 대량은 기존 R-EDIT 작업과 비교한다. 발주서에서 문구를 준비하는 시간부터 입력·생성·검토·수정·Type3 마무리까지 측정한다. 이미 정리된 Excel만 비교해 입력 준비 부담을 빠뜨리지 않는다.

개별 수정한 항목 수와 수정 시간, 전체 작업 시간, 관리자 개입 횟수, 원문·수량 오류를 기록한다. 복제 수량을 수정률 분모에 섞지 않는다. 시간 단축과 허용 수정률의 목표 수치는 기준 작업을 측정한 뒤 정한다.

Type3 확인 결과와 남은 범위

T03의 두 줄 표시와 그룹 해제 후 줄별 객체 분리는 확인됐다. 후속 전체 문구 유니코드 표기 시험에서 R2000·R2004 모두 정상 표시됐고 R2000을 기본으로 정했다. U 깨짐의 내부 원인은 확정하지 않았다. 베트남어 등 특수 문자·다른 폰트·직접 편집·정밀 치수는 별도 검증 대상이다.

15 출력 전달과 추가 요구사항

수량과 생산 안내

Type3의 많은 객체에 따른 지연과 생산자의 수량 누락을 함께 줄여야 한다. 복제 출력은 도안 수가 실제 수량이 되게 하고, 수량 표시 출력은 해당 명판과 수량의 연결을 분명히 한다. 어느 방식인지 눈에 띄며 수작업으로도 따라 할 수 있는 표기를 검증한다. 한 파일에 한 방식만 강제할지는 아직 정하지 않는다.

자재·두께·색상·수량·필요시 프로젝트를 제품 문구와 구분한다. 안내는 고객사, 자재·두께·색상, 수량, 프로젝트 순으로 줄을 나누고 프로젝트가 없으면 생략한다. 출력 도안은 좌하단부터 오른쪽·위쪽으로 나열한다. 정보는 좌상단에 둘 수 있다. 프로젝트·자재별 구분과 분리 포장 정보가 이어져야 한다. 상세 표기와 간이 식별표는 후속 검토이며 NC·판재 배치는 제외한다.

R23 재료와 두께를 반영한 제품 미리보기

상태: 필요 확인  |  구현 수준과 개발 순서: 보류

2D 디자인에 재료의 외관, 제품 두께, 간단한 음각 표현 등을 적용해 실제 느낌을 보며 검토할 수 있어야 한다. 1T·1.5T 같은 두께 차이를 표현하되 도구 경로나 제조 결과를 정밀하게 시뮬레이션하는 범위로 확대하지 않는다. 2D 배치의 정확성과 Type3 호환성 검증을 먼저 진행한다.

업무 개념의 구분

발주 아래 선택적 복수 프로젝트, 디자인별 작업과 생산 항목을 연결한다. 생산 항목은 문구·수량·제작 조건을 담고 배치 결과는 줄바꿈·크기·자폭·위치를 담는다. 출력 배치는 복제와 생산 안내를, 출력 이력은 채택 결과와 재출력 관계를 담는다. 특정 화면 수나 데이터베이스 구조를 지정하지 않는다.

등록과 변경의 구분

도안자는 승인된 방식과 허용 범위 안에서 만든 새 디자인을 다른 직원이 선택해 재사용하도록 등록할 수 있다. 이 등록 자체에는 관리자 승인이 필요 없다. 고객사·태그·선택적 프로젝트·치수·홀 등은 검색과 적용 판단에 활용한다. 일회성 작업은 공통 등록 없이도 저장 기록이 남는다.

기존 공통 자동 배치 기준을 바꾸거나 허용 범위 밖 특별 규칙을 적용하는 경우에는 관리자 최종 승인을 받는다. 누구나 문제와 개선안을 남길 수 있다. 정상 작업마다 승인받는 절차로 확대하지 않는다. 승인된 자동화 방식이라는 점을 분명히 하여 반복적인 주관적 재검토를 줄이는 것이 목적이다.

과거 결과와 개선 기준의 공존

기존 디자인과 진행 중 주문은 적용 중인 기준을 유지한다. 공통 기준 개선은 결과를 비교한 뒤 명시적으로 채택한다. 새 문구 추가나 프로그램 업데이트가 과거 배치를 바꾸지 않게 한다. 필수 조건 위반이 확인된 결과는 재검토 대상으로 구분한다. 일반 직원에게 버전·병합·PR 이해를 요구하지 않는다.

공통 패턴 요구와 구현의 분리

반복 구절만으로 설치 관계를 단정하지 않는다. 고객사·선택적 내부 구분·디자인과 가변 부분을 함께 본다. 프로젝트가 달라도 참고할 수 있다. 일반 결과는 자동 선택하며 작업자가 매번 묶음이나 미관 후보를 골라야 하는 흐름을 기본으로 삼지 않는다.

동일 제품과 유사 문구의 구별

같은 디자인·같은 문구는 채택한 배치 자체를 재사용한다. 같은 디자인의 새 문구는 과거 공통 부분의 배치를 참고해 생성한다. 다른 디자인에서는 표현의 묶음과 줄바꿈 경향을 참고할 수 있지만 좌표·글자 크기·자폭을 그대로 복사하지 않는다. 다른 디자인 간 참고 방식은 미검증이다.

이어받은 과거 작업의 연결은 작업 과정에서 남겨야 한다. 같은 크기만으로 동일 디자인이라고 판단하지 않는다. 내부 식별 방식과 검색 UI는 아직 선택하지 않았다.

원문, 실제 줄바꿈, 영역별 글자 크기, 줄별 자폭·위치, 디자인·적용 기준과 채택 시점을 함께 남긴다. 생성 조건만 저장하면 알고리즘 변경 뒤 과거 모습을 보장할 수 없으므로 채택 결과를 보존한다. Type3 파일은 사람이 참고하는 연결 자료이며 자동 기준으로 해석하지 않는다.

R28 서로 다른 과거 배치의 충돌

상태: 합의  |  우선순위: 핵심  |  관련 요구: R17 R19 R22

이번 작업에서 이어받은 기록, 고객사 내부 구분, 명시적인 기준 대체 관계로 먼저 구별한다. 해결할 근거가 없으면 자동 확정을 보류하고 차이가 있는 부분을 사람이 확인한다. 최신 날짜·최다 사용 횟수만으로 하나를 선택하지 않는다. 같은 배치가 여러 번 출력된 것은 서로 다른 배치 충돌과 구별한다.

철회한 조건과 시험 가정

이전 P07의 프로젝트 차단 조건은 폐기했다. 고객사·선택적 내부 구분을 사용한다. 시험에서 사용한 경계 감점 18, 자폭 차이 감점 3, 추가 자폭 감소 5%p 제한, 탐색 폭 128은 확정 생산 기준이 아니다. 한 영역의 동일 글자 크기·줄별 자폭은 공통 합의다.

남은 핵심 검증

복수 영역·자유로운 홀·조각과 인쇄·명시적 실행은 기능 시안으로 일부 확인했다. 패턴과의 통합, 다양한 폰트·문자, 다른 PC, 실제 가공, 전체 작업시간 검증은 남았다. 기존 이력 시험과 최근 UI 상태 시험은 제품 전체의 통과를 뜻하지 않는다.

검증 자료

nameplate_common_patterns_v02.html의 H01~H06에 과거 고정 배치, 다른 프로젝트 추가 주문, 수동 수정·재출력, 내부 구분, 충돌, 일회성 예외를 기록했다. 같은 자료의 보관본에 이전 P01~P09를 남기고 폐기된 프로젝트 조건을 표시했다.

문헌은 설계 원칙의 보조 근거다. NASA의 라벨 일관성 지침과 영어 줄바꿈 선호 연구를 참고했지만 명판의 구체적인 가중치·커터 한계를 도출한 것은 아니다. 영어 의미 단위 개선을 우선하며 한글의 언어적 줄바꿈 고도화는 후속으로 남긴다.

22 소량 주문의 입력부터 출력까지 검증

검증할 작업 흐름

고객사와 기존 디자인 선택 → 발주서를 보며 문구 붙여넣기·직접 입력 및 수량 지정 → 과거 기록과 자동 배치를 표·도안으로 확인 → 필요한 문구·줄바꿈 수정 → DXF 내보내기. 3종 4개가 누락 없이 전달되고 별도 기록 등록 없이 다음 주문에서 활용되어야 한다.

프로그램 안에서는 여러 줄 텍스트를 한 영역으로 편집한다. 한 영역의 크기는 공통으로 유지하고 줄별 자폭은 조정한다. DXF가 줄별 TEXT로 나뉜다는 이유로 작업자가 줄 객체를 하나씩 편집하도록 요구하지 않는다.

통과 기준과 측정

원문과 수량 보존, 수정한 문구만 변경, 과거 배치 불변, 표와 미리보기의 일치, 출력 기록 재사용을 확인한다. 출력 수량을 복제 또는 수량 표시로 표현할 때 대상 연결과 총수량이 같아야 한다. 화면은 실제 담당자가 설명을 최소로 듣고 완료할 수 있는지 본다.

발주서 확인·문구 준비·디자인 찾기·입력·자동 생성·수정·출력 시간을 나눠 측정한다. Type3 마무리는 프로그램 밖 단계로 따로 재되 전체 작업량에 포함한다. 기존 소량 수작업과 비교하고 멈칫한 지점·도움 요청·오타 의심 오탐·수정 항목 수를 기록한다. 시간 단축률이나 클릭 수 목표는 아직 확정하지 않는다.

v0.5 변경 요약

R09·R10·R14~18·R20을 갱신하고 R26~28을 추가했다. 동일 디자인의 경계, 고객사 범위, 프로그램 내 편집 완료와 출력 시 채택, 작업별 재출력, 복수 프로젝트 구분을 반영했다. Type3 관찰·자동 검사·미검증을 분리했다. 기술과 제품 UI 선택은 계속 보류한다.

23 디자인 구성과 문구 입력의 최신 요구

R29 일반 명판을 자유롭게 구성

상태: 합의. 홀 개수·배치를 고정하지 않는다. 좌우·상하·십자 배치와 3개·5개·6개 등 필요한 수를 추가하고 위치·지름을 직접 지정한다. 외형 치수·모서리 라운드·홀의 가장자리 거리 등 자주 쓰는 값을 쉽게 입력한다. 특정 세 가지 명판 유형 중 하나를 고르는 방식으로 제한하지 않는다.

텍스트 영역도 필요한 수만큼 추가하고 배치한다. 영역 이름은 사용자가 정하며 표의 열 이름과 연결한다. 한 줄과 여러 줄은 영역의 배치 조건으로 다룬다. 홀·외형·테두리·장식·텍스트 영역을 수정하는 디자인 작성과, 정해진 디자인에 문구를 넣는 단계는 분리한다.

R30 필수 공간 조건과 제작 방식

상태: 합의. 글자는 지정한 허용 도형 안에 있어야 한다. 기본은 명판 외곽이며 테두리 안쪽 등으로 지정할 수 있다. 장식과 구분선의 회피 조건은 29절을 따른다. 원형 홀의 회피 범위는 홀 반지름에 0 이상의 추가 여유를 더한다. 추가 여유는 나사·리벳 머리와 가림 가능성을 고려해 정하고 홀 자체보다 작게 설정할 수 없다.

조각인지 인쇄인지 디자인 준비에서 지정한다. 조각에는 해당 디자인의 자재·폰트·커터 경험 기준을 적용하고 인쇄에는 적용하지 않는다. 일반 직원에게 커터 계산식을 조작하도록 요구하지 않는다. 경험 기준과 정밀 가공 가능성 판정은 구별한다.

R31 입력과 배치를 명확히 구분

상태: 합의. 문구·설정을 바꿔도 입력 중 자동으로 줄바꿈을 반복하지 않는다. 배치 버튼으로 갱신하고 이전 결과에는 미반영 상태를 표시한다. 표의 셀과 미리보기의 명판·영역 선택을 연결하며 미리보기에서도 문구를 편집할 수 있어야 한다.

재배치 전후 비교, 수동 줄바꿈과 줄별 자폭 편집을 지원한다. 수동 수정 유지·해제의 구체적인 기본값은 미정이다. 첫 개발에서는 수정값이 조용히 사라지지 않도록 하고 출력할 내용이 최신인지 확인한다. 오래된 결과의 출력 방지 동작은 27절 제안 기준에 포함한다.

일반화 범위

MRCE 75 × 25 mm의 3줄 선호·4.5 mm·자폭 80%는 그 디자인의 사례다. 다른 디자인의 줄 수·크기·자폭으로 확장하지 않는다. 시험 도구의 8줄·40 mm·자폭 200% 같은 계산 한도도 제품 요구사항이 아니다.

적용 범위가 좁다는 이유만으로 모든 항목을 무조건 우선하지 않는다. 기준 충돌은 처음 구성할 때 해결하고 일상 주문마다 작업자에게 선택을 떠넘기지 않는다. 충돌 해결과 배치 후보의 미관상 절충은 다른 문제다.

사용자가 조정할 내용

기본 글자 모습, 긴 문구 맞추기, 줄 길이 균형, 함께 읽는 표현 유지, 유사 문구 통일, 과거 배치 유지처럼 업무상의 동작으로 보여주는 안을 사용한다. 명확한 값·허용 범위·선호 강도를 구분하며 모든 항목을 점수 슬라이더로 만들지 않는다.

영어 의미 단위와 공통 패턴은 적용한 고객사·디자인에서 사용한다. 원문은 임의 교정하지 않는다. 사용자 사전의 고객사·프로젝트 범위와 공통 패턴의 고객사·선택적 내부 구분 범위도 혼동하지 않는다.

개발과 업무 설정의 경계

새 판단 로직은 개발자가 구현한다. 도안 담당자는 준비된 동작·값·적용 범위 안에서 조율한다. 기존 공통 기준 변경이나 허용 범위 밖 예외는 관리자 최종 확인을 거치며, 허용 범위의 새 디자인 등록과 정상 주문은 반복 승인을 요구하지 않는다.

25 초기 조율과 기준 갱신

R33 여러 문구를 이용한 초기 조율

상태: 기능 흐름의 초안 채택. 처음에 충분히 조율한 기준을 쉽게 가져와 쓰는 것이 목표다. 지속적인 학습이나 매 주문의 수동 예외 축적을 기본 운영으로 삼지 않는다.

실제 문구와 가상 시험 문구를 구분한다. 짧은·긴 문구, 긴 단어가 앞·중간·끝에 오는 경우, 여러 영역, 유사 문구 묶음, 이전 채택 결과를 함께 시험한다. 극단 사례를 맞추려고 일반 주문 품질을 떨어뜨리지 않으며 시험 문구는 생산 수량에서 제외한다.

결과 선택 → 해당 영역 기준 조율 → 전체 시험 배치 → 변경 전후와 다른 결과 확인 → 사용할 기준 기록의 흐름을 채택한다. 현재 시안은 선택 영역만 조정하고 직접 실행한 뒤 비교한다. 괜찮음·더 조율·미확인 표시는 초기 검토 보조이며 생산 승인이나 가공 품질 보증이 아니다.

배치 결과가 바뀐 항목만 이전 판단을 미확인으로 돌리는 것은 UI 초안이다. 같은 결과의 판단은 유지하되 제작 조건 자체의 변경이나 새 오류 발견 시 재검토 범위는 별도로 정해야 한다. 평소 주문마다 모든 결과에 확인 버튼을 누르게 하지 않는다.

R34 공통 기준 개선과 기존 작업 보호

상태: 과거 보존 원칙은 합의, 갱신 절차는 초안. 공통 기준 수정만으로 기존 디자인·진행 중 주문을 재배치하지 않는다. 변경 내용과 영향받는 결과를 비교한 뒤 해당 디자인에 적용한다. 오류 수정도 표시 결과가 달라질 수 있으므로 자동 전파하지 않는다.

이 디자인에서 따로 정한 값은 유지한다. 새 기준과 함께 사용할 수 없으면 충돌을 설명한다. 공통 변경의 승인은 관리자에게, 시험·개선안 작성은 도안 담당자에게 허용한다. 필수 조건 위반이 발견된 결과는 재검토 대상으로 표시한다.

재현을 위해 남길 정보

디자인·입력 문구·수량·적용 기준과 값·계산 방식 식별·폰트 식별·실제 배치와 수동 수정·내보내기 이력을 함께 연결한다. 조건만으로 과거 배치가 영구 재현된다고 가정하지 않는다. 저장한 채택 결과를 재사용하며 모든 과거 실행 엔진을 영구 운영하는 기술 구조까지 확정하지 않는다.

개발 구조를 고르기 전: DXF 가져오기 객체 범위, 폰트 측정·출력 경로, 로컬 저장·공유·복구·배포 방식과 비용을 비교한다. 자동 배치 상세 설계에서: 기준 중복 식별·우선 관계·점수, 패턴 검출, 수동 수정 유지 정책을 구체화한다. 현장 시범 사용 전: 실제 폰트·Type3·가공과 소량 작업시간을 확인한다.

이번 개정 내용

R01·R04·R06·R09·R10·R12·R16·R24와 운영 기록을 보완하고 R29~R34를 추가했다. 첫 개발 범위·완료 기준·시안 한계를 분리했다. 기준 조율 UI는 초안으로 진행하며 상세 화면 검토를 계속 늘리지 않는다. 기술 스택과 운영비는 아직 확정하지 않았다.

29 테두리와 장식 도형의 역할

R35 디자인 도형과 배치 제약

상태: 테두리·장식 포함과 사람이 역할을 지정하는 요구는 합의. 아래 제약 연결과 미지정 처리 방식은 구현 초안이다. R01~03·R30을 보완하며 첫 개발 범위에 포함한다. 기존 시안의 외형·홀·텍스트만으로 지원을 완료한 것으로 보지 않는다.

도형의 모양과 업무상 용도는 별도로 기록한다. 같은 원이라도 홀 또는 장식일 수 있고, 여러 선이 하나의 테두리를 구성할 수 있다. 용도를 정한 뒤 글자가 들어갈 범위·피할 부분·내보낼 대상을 연결한다.

쉽게 보이되 서로 다른 의미는 구분

화면에서는 도형을 선택해 용도를 지정하고, 필요한 경우에만 “이 안에 글자 넣기”·“이 부분 피하기”·“출력에 포함”을 확인하는 안을 검토한다. 기본값으로 조작을 줄이되 테두리라는 이름 하나로 모든 텍스트 영역의 경계를 바꾸지 않는다.

선과 겹치지 않게 할 때는 표시·출력에 사용하는 선의 폭과 추가 여유를 고려한다. 선만 피할지 내부까지 피할지는 구분한다. DXF에서 폭을 알 수 없는 경우 적용할 폭은 미정이며, 조각 커터 경로를 생성하거나 정밀 가공 가능성을 보장하는 기능으로 확대하지 않는다.

텍스트 영역, 선택한 안쪽 경계, 명판 외곽과 회피 영역을 함께 반영한다. 조건을 만족할 공간이 없으면 배치 불가로 표시한다. 수동 문구 편집도 같은 검사를 받으며 홀이나 필수 경계를 점수로 무효화하지 않는다.

30 DXF에서 가져온 도형의 지정과 검증

처음 디자인을 준비할 때 지정하고 재사용

DXF 가져오기 → 도형 확인과 묶음 선택 → 용도와 배치 영향 지정 → 사용할 디자인 저장의 흐름을 초안으로 둔다. 레이어·색상·기존 그룹·형상은 선택과 후보 제안에 활용할 수 있지만 역할을 확정하는 근거로 단독 사용하지 않는다. 모든 원을 홀로, 가장 큰 사각형을 무조건 명판 외곽으로 처리하지 않는다.

여러 도형을 선택해 한 번에 같은 역할을 지정할 수 있어야 한다. 여러 선으로 구성된 테두리는 함께 지정한다. 끊긴 선을 닫힌 경계로 쓸 수 없으면 끊긴 위치와 확인할 대상을 보여주고, 임의로 선을 이어 원본을 바꾸지 않는다. 구체적인 선택 UI는 후속 설계한다.

미지정 도형은 도면에 그대로 보존하고 “용도 확인 필요”로 표시한다. 작업 중 저장은 허용하되 배치·출력 영향이 확인되지 않은 상태를 정상 완료로 취급하지 않는 안을 제안한다. 남은 객체를 묶어 장식·참고용 등으로 확인할 수 있게 해 매 선마다 반복 입력하는 부담을 줄인다.

저장한 디자인의 도형·역할·대상 텍스트 영역·회피 여유·출력 여부를 함께 재사용한다. 새 주문마다 다시 지정하지 않는다. 문구 자동 배치 단계에서는 이 형상과 역할을 고정하며, 바꾸려면 디자인 편집으로 이동한다. 기존 주문에는 변경을 자동 전파하지 않는다.

도형 보존과 출력

테두리·장식은 미리보기뿐 아니라 최종 DXF에도 포함되어야 한다. 참고용 제외는 명시적으로 확인한다. 지원하지 않는 DXF 객체는 가져오기에서 알리고, 화면에서 빠뜨린 채 성공 처리하거나 출력 때 조용히 버리지 않는다. 지원 객체 종류·변환 허용 범위는 기술 검증 후 정한다.

C09 추가 완료 판단 기준

R01~03 R30 R35: 같은 원 두 개를 홀과 장식으로 구분한다. 외곽·테두리·열린 장식선·복수 텍스트 영역이 있는 사례에서 지정한 영역만 경계의 영향을 받는지 확인한다. 여러 선으로 된 테두리와 미완성 경계도 시험한다.

역할 지정 전후 원본 형상이 보존되고, 미지정·지원 불가 객체가 숨겨지지 않아야 한다. 배치가 홀·경계·지정 장식을 침범하지 않는지, 저장 후 다시 열어도 역할이 유지되는지, Type3에서 제품 도형과 편집 가능한 문구가 함께 전달되는지 확인한다.

현재 상태: 요구사항 보완이며 위 기능의 구현·호환 시험 통과를 뜻하지 않는다. 기존 112개 배치 검사 결과에 이 도형 사례들이 포함된 것으로 해석하지 않는다. 이번 개정은 R01~03·R30·첫 개발 범위와 검수 기준을 연결하고 R35·C09를 추가한 것이다.
