첫 목표는 정해진 디자인에 문구를 넣고 배치한 뒤, 수정·저장·복원·출력까지 한 번에 이어지는 작업을 만드는 것이다. 소량 입력도 편해야 하며, 작업자가 바뀌어도 같은 기준으로 배치되어야 한다.

채택한 개발 방향

Flutter와 Dart를 중심으로 하나의 앱과 저장소에서 개발한다. 도안 데이터는 우리 프로그램이 소유하고, 파일 입출력·폰트 측정·배치 계산의 구현은 교체 가능한 경계로 분리한다. Python은 제품의 필수 구성에 넣지 않는다.

첫 연결 구현과 전체 개발 범위

첫 연결에서는 준비된 디자인을 사용한다. 텍스트 영역 1개와 여러 개, 소량 직접 입력과 Excel 붙여넣기를 모두 다룬다. 전체 디자인 편집기와 규칙 조율 화면도 개발 범위에 유지하며, 첫 연결 다음에 확장한다.

DXF·폰트의 추가 기술 검증은 현재 보류한다. 임시 출력 구현으로 연결을 확인할 수 있지만, 실제 Type3 호환성 확인 전에는 생산 적용 완료로 보지 않는다. NC 생성과 Type3 외부 수정 추적은 범위에 포함하지 않는다.

먼저 분리할 샘플 조건

75×25, 기본 4.5mm, 자폭 80%, 3줄 선호는 MRCE 시험 디자인의 값으로 이동한다. 모든 디자인의 기본값으로 사용하지 않는다. 영어 의미 단위·공통 패턴도 적용 범위를 가진 규칙으로 옮긴다.

22단어·250자·500행 같은 기존 시험 한도는 제품 요구사항이 아니다. 처리량 기준은 실제 사용 PC에서 확인한 뒤 정한다. 기존 112개 영역 검사나 286행 입력 사례는 검증 자산이며 제품 지원 범위를 보증하지 않는다.

2 첫 구현 작업 목록

작업 순서는 아래와 같다. 공통 검색 화면·업무 상태 관리보다 도안 작업의 연결을 먼저 만든다. 일정을 임의로 추정하지 않고, 각 작업은 결과와 완료 기준으로 관리한다.

W01 도안 데이터와 저장 구조

디자인, 영역, 주문별 문구 행, 수량, 적용 기준, 배치 결과를 Dart 데이터로 정의한다. 표시 이름과 별개인 ID로 연결한다. 완료: 같은 문구가 여러 행에 있어도 수량과 수동 조정이 섞이지 않고, 저장·복원 후 데이터가 유지된다.

W02 교체 가능한 처리 경계

W01 이후 파일 입출력·폰트 측정·배치 계산의 입력과 결과를 정의한다. 시험용 구현부터 연결한다. 완료: 처리 구현을 바꾸어도 화면과 저장 형식을 함께 수정할 필요가 없다. 범용 플러그인 시스템은 만들지 않는다.

W03 표와 미리보기 연결

W01 이후 1행당 명판 하나, 영역별 문구 열과 수량으로 구성한다. 직접 입력·범위 붙여넣기·양쪽 선택 연결을 구현한다. 완료: 문구가 여러 개인 명판도 별도 데이터 변환 단계 없이 입력하고 편집할 수 있다.

W04 배치와 수동 수정 연결

W02·W03 이후 버튼 실행으로 계산한다. 원문과 자동 줄바꿈을 구분하고, 수동 지정과 적용 대상을 기록한다. 완료: 문구·설정 변경이 미반영 상태로 보이며, 유지하기로 한 수동 조정은 재배치로 사라지지 않는다.

W05 여러 디자인과 기록 유지

W01·W04 이후 한 발주에서 여러 디자인 작업을 유지한다. 프로젝트는 선택 항목이다. 완료: 다른 디자인의 문구·결과가 섞이지 않고, 작업 저장만으로 일회성 디자인과 확정 결과도 다시 열린다.

W06 출력 연결

W02·W04·W05 이후 확정된 결과를 출력기에 전달한다. 고객사·자재·두께·색상·수량·선택 프로젝트를 함께 전달한다. 완료: 출력 단계에서 배치를 다시 계산하지 않고, 어느 작업 결과를 내보냈는지 기록한다.

W07 전체 흐름 확인

W01~W06 이후 4쪽 사례로 입력부터 재열기·출력까지 확인한다. 완료: 미반영 결과·다른 디자인·수량을 혼동하지 않는다. Type3 확인과 직원 PC 시험은 별도 생산 적용 단계로 남긴다.

구현 전에 좁혀야 할 세부 사항

수동 줄바꿈·자폭을 어느 단위로 유지할지, 문구 변경 시 어떻게 무효화할지는 W04에서 정한다. 임시 수정을 공통 규칙이나 과거 표준으로 자동 승격하지 않는다. 규칙 조율에서는 영향받는 결과를 보여주고, 다른 직원에게 영향을 주는 변경의 승인 경계를 유지한다.

수량을 복제할지 표시할지는 출력 방식으로 구분하고 실제 주문 수량은 하나로 관리한다. 수량만 바꾸면 문구 배치를 다시 풀 필요는 없지만, 출력 배열·수량 표기·출력 기록의 갱신 여부는 따로 확인해야 한다.

홀·허용 경계 침범이나 배치 실패는 진단 화면에 보여줄 수 있다. 이를 정상 생산 결과와 구분하는 처리가 필요하다. 실제 임의 장식·경계의 정밀 판정은 후속 도형 기능과 함께 검증하며, 첫 연결 성공만으로 완료 처리하지 않는다.

5 후속 범위와 착수 순서

첫 연결 이후에도 유지할 개발 범위

직접 도형 편집과 DXF 역할 지정, 초기 배치 기준의 조합·영향 확인·승인, 고객별 과거 참조 검색을 이어서 구현한다. 단순 배치 연결만 끝낸 상태를 직원에게 배포할 최종 자동화로 보지 않는다. 줄바꿈과 자폭 수작업을 충분히 줄이는 것이 제품의 핵심이다.

보류한 내용

DXF·폰트 세부 기술 검증, 서버·공유 정보 저장 방식·업데이트 도구 선택은 현재 문서에서 확정하지 않는다. 고객 전용 접속은 보류하고, 고객 검토 보고서 내보내기는 추후 검토한다. sERP 연동·원가 계산·배송 상태 추적도 첫 연결 구현에 넣지 않는다.

착수 지점

다음 작업은 W01이다. 시험 디자인 세 가지와 문구 행을 새 데이터 구조로 표현하고, 저장 후 다시 읽었을 때 확정 결과가 유지되는지 확인한다. 이때 75×25 샘플 수치를 기본값으로 심지 않는다. 그다음 W02와 W03을 연결한다.
