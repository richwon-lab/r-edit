리치원 도안 데이터 논리 설계 초안

2026년 10월 18일  ·  버전 0.1

명판 1~2개도 부담 없이 입력·배치·출력할 수 있는 구조를 먼저 마련한다. 제품과 도안의 관계를 정리하고, 현재 작업 저장·과거 파일 참고·줄바꿈 자료를 목적에 맞게 구분한다. 아래는 논리 설계안이며 DB 테이블이나 코드 명칭을 확정한 것은 아니다.

최소 입력

기존 디자인을 선택하고 문구를 입력하면 배치를 확인하고 출력할 수 있어야 한다. 직접 만든 새 항목의 수량 기본값은 1개를 제안한다. 발주 자료에서 수량을 읽지 못한 경우에는 임의로 1개로 채우지 않는다.

항목 식별 정보, 계산 결과, 사용 기준, 출력 대상·수량은 프로그램이 관리한다. 과거 참고는 실제 작업 파일을 연결한다. 줄바꿈 자료를 위한 중복 입력은 요구하지 않으며, 자료 채택 조건은 추후 정한다. 이번만 쓰는 디자인도 공용 등록 없이 사용할 수 있게 한다.

3 현재 작업 저장과 과거 파일 참고

작업 파일 전체의 제품에 현재 입력과 맞는 배치가 있고, 각 제품이 정상 판정이거나 작업자가 결과를 확인한 때 저장한다. 저장 요청 시 필요한 대상만 계산하고 확인이 필요한 결과를 모아 한 번에 확인할 수 있게 한다. 입력·적용 조건·배치·판정과 확인을 함께 저장한다. 다시 열 때는 저장된 결과를 사용하며, 글꼴 자료와 계산 엔진의 식별 정보는 재계산할 때 확인한다.

과거 파일 연결과 줄바꿈 자료

과거 작업을 참고할 때는 발주와 실제 작업 파일을 연결한다. DXF·Type3 등에서 추가 조작했을 수 있으므로 프로그램의 과거 배치를 실제 제작 도안으로 간주하지 않는다. 과거 참고를 위해 작업 전체를 복원하는 이력은 요구하지 않는다.

줄바꿈 자료는 필요한 문구·줄 구성·관련 적용 조건·출처를 선별해 관리한다. 한 줄 결과는 줄바꿈 참고·학습 대상에서 제외한다. 현재 작업의 한 줄 배치와 직접 지정 상태는 재개·출력을 위해 유지한다. 수량은 줄바꿈 자료의 조건으로 사용하지 않는다.

작업 파일 연결과 줄바꿈 자료는 목적을 구분하며 같은 저장소에서 관리할 수 있다. 수집은 출력 파일이 정상 생성된 때 수행한다. 수집한 사례를 최종 정답이나 공용 패턴으로 자동 채택하지 않는다. 학습에 사용할 자료의 선별과 학습 방식은 추후 정한다.

패턴 적용의 현재 기준

한 문구에 여러 패턴이 일치하는 것은 정상적인 상황이다. 함께 지킬 수 있으면 모두 반영한다. 포함 관계에서 충돌하면 더 구체적인 문구의 패턴을 우선하고, 별도의 우선순위 설정은 도입하지 않는다. 영향 패턴 수와 목록은 확인할 수 있게 한다. 포함 관계가 아닌 충돌은 실제 고객 사례로 판단한다.

4 공정별 파일과 후속 설계

판재 준비를 위한 절단과 완성 제품의 외곽 가공은 구분한다. 시트지 인쇄물은 인쇄 후 커팅하며, 알루미늄·페놀의 특정 형상에는 CNC 가공이 필요할 수 있다. 특수 형상 가공과 인쇄의 순서는 아직 고정하지 않는다.

주문 수량, 해당 파일에 포함한 제작 수량, 실제 그린 도안 개수를 구분한다. 같은 제품이 여러 공정을 거쳐도 주문 수량을 합산하지 않는다. 수량 표시 방식에서는 도안 1개가 제작 수량 여러 개를 나타낼 수 있다.

아직 결정하지 않은 항목

의도한 빈 문구와 읽지 못한 입력을 구분하는 조작, 줄바꿈 자료의 학습 대상 선별·보존 정책과 폴더명·확장자는 미정이다. Drive 저장 단위는 9장, UTF-8 JSON과 DXF 문자 호환 기준은 10장에서 정리한다.

내부 저장은 UTF-8 JSON으로 시작한다. 세부 필드·클래스명·변수명과 조회·학습 알고리즘은 확정하지 않았다. 현재 작업 상태와 계산 조건은 프로그램이 관리하며 과거 참고용 파일 연결을 위해 복잡한 기록 입력을 요구하지 않는다.

구현 시 먼저 확인할 사례

① 발주 상세 정보 없이 명판 1개를 배치·저장·재열기·출력한다. ② 같은 문구의 수량과 직접 지정 줄 구성이 섞이지 않는다. ③ 수량 변경은 배치를 유지한다. ④ 공용 기준이 바뀌어도 저장된 작업은 유지된다. ⑤ 과거 참고는 연결한 실제 파일을 연다. ⑥ 한 줄 자료 제외와 현재 작업 재개를 구분한다.

로컬 구현에서 확인할 예시

같은 내용의 재출력이나 수량만 바꾼 출력에서는 신규 사례가 0건이다. A의 줄 구성을 다르게 해 출력하면 신규 사례는 1건이다. 출력 파일 일부의 실패로 전체 출력이 실패하면 수집은 0건이다.

이는 로컬 구현용 검증 기준이다. 이번 문서 수정에서 수집 기능을 개발하거나 해당 시험을 실행한 것은 아니다.

저장의 영향 범위

파일 1 저장은 파일 1의 입력·결과만 갱신하며 다른 파일이나 발주 전체를 덮어쓰지 않는다. 자동 문구 그룹은 현재 파일 안에서 구성하며 같은 발주의 다른 파일과 수정·재계산을 연동하지 않는다. 미완료 편집·재계산 대상·계산 작업 식별 정보·진행 상태는 파일별 메모리에서 관리하고 저장 파일에 넣지 않는다.

공용 디자인·패턴의 원본 수정은 진행 중 파일에 자동 적용하지 않는다. 서로 다른 공용 항목과 작업 파일별 줄바꿈 자료는 별도 파일로 저장하며, 같은 공용 항목의 동시 수정은 초기 지원에서 제외한다. 인수인계는 이전 저장 내용이 Drive에 동기화된 뒤 진행한다.

필요하면 각 PC에 검색용 자료를 만들 수 있지만 공유 원본에서 다시 만들 수 있는 임시 자료로 취급한다. 최초 구현에 검색 DB나 별도 학습 알고리즘을 필수로 두지 않는다.

① 두 작업 파일이 동시에 서로 다른 자료 파일을 저장해 양쪽 내용이 유지된다. ② 같은 사례를 담은 자료 파일 두 개를 읽으면 사례는 하나로 묶고 두 출처를 유지한다. ③ 같은 작업의 재출력·수량 변경으로 사례가 늘지 않는다. ④ Drive 동기화 후 다른 PC에서 작업과 사례를 이어서 저장한다.

위 항목은 실제 PC와 Drive 환경에서 확인할 검증 기준이다. 문서 갱신 과정에서 동기화 기능을 개발하거나 시험한 결과는 아니다.

저장 규약

자료 종류·고유 식별 정보·저장 형식 버전·실제 내용을 보관한다. 저장 형식 버전은 계산 엔진 식별 정보와 구분한다. 문구의 공백·대소문자·기호를 임의로 바꾸지 않는다. 필수 값 누락이나 잘못된 구조를 0 또는 임의의 기본값으로 보정하지 않는다.

공용 기준은 별도 지정 없음·값 지정·사용 안 함을 구분한다. 원본에는 상속과 지정 의도를, 작업 파일에는 결합된 실제 계산 조건과 출처를 보존한다. 끌 수 있는 선택 규칙과 원문 보존·홀 회피·허용 경계 같은 필수 조건을 구분한다.

DXF와 실제 프로그램의 확인 범위

Autodesk 문서상 UTF-8 DXF는 AutoCAD 2007 이상 형식에서 지원한다. 이전 형식의 문자 표현과 코드페이지는 별도로 다뤄야 한다. 기존 시험 코드에서 R2000·CP949 설정을 확인했으나, 이를 Type3의 모든 한글·기호 지원 보증으로 확대하지 않는다.

표현할 수 없는 문자를 임의로 물음표로 바꾸지 않는다. 한글과 Ø Φ × ± ℃ 등 실제 사용 문자에 대해 Type3·CAD의 이스케이프 해석과 글꼴 지정도 함께 확인한다. 저장 후 재열기 검증은 원문·줄 경계·규칙 상태·배치 결과의 보존을 확인한다.

근거: Dart JSON · Autodesk DXF 문자열 규격 · ezdxf 문자 인코딩

문서에 저장 규약을 반영했다. 이번 갱신에서 앱 저장 기능을 구현하거나 Type3 실기 시험을 추가로 실행하지 않았다.
