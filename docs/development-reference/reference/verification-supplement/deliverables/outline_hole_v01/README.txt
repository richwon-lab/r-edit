리치원 글자 윤곽·홀 회피 비교시험 v0.1

실행
1. 압축을 모두 풀고 preview.html을 열면 기존 결과와 6개 비교 사례를 봅니다.
2. 재실행은 Python 3.10 이상으로 experiment.py 실행. 외부 패키지는 필요 없습니다.
3. results.json / audit.json / preview.html이 스크립트 옆에 생성됩니다.
4. 자동 검사 모두 통과 시 종료 코드 0, 검사 실패 시 1입니다.

이번 결과
- 기존 100행의 본문·NO·RAT 300영역을 읽기 전용으로 검사합니다.
- 글자-홀 조합 5,754개를 검사합니다. 기존 좌표·크기·자폭·줄바꿈은 바꾸지 않습니다.
- 이번 입력에서 윤곽 검사 통과 298영역, 침범 확인 0영역, 판정 불가 2영역입니다.
- 판정 불가: R044/MCB39 본문 2번째 줄 P, R047/MCB42 본문 2번째 줄 D.
  두 건 모두 왼쪽 홀 중심부터 형상까지의 계산 거리가 약 4mm이고 요구 반경도 4mm입니다.
  입력 형상 기준으로 사실상 접촉한 사례로, 수치 경계의 불확실성을 통과로 바꾸지 않습니다.
- 자동 검사 24/24 통과는 두 판정 불가 사례가 제대로 보고된 것까지 포함합니다.
  300영역 전부를 새 검사에서 통과시켰다는 뜻은 아닙니다.

구현 범위
- 저장된 HY세고딕의 SVG 경로 M/L/H/V/Q/Z를 읽습니다. 94개 비공백 경로를 검사합니다.
- 각 글자의 위치에 누적 문자 간격, 기존 글자 크기 환산과 가로 배율을 한 번 적용합니다.
- 여러 윤곽의 방향을 합산하는 nonzero 채움 규칙으로 O 등의 내부 빈 부분을 구분합니다.
- 곡선을 직선으로 나눌 때 Q(t)와 현(chord) 사이의 최대 편차 상한을 추적합니다.
- 거리의 하한·상한으로 판정하며, 애매하면 0.001mm부터 0.0000001mm까지 정밀도를 높입니다.
- 부동소수점 수치 여유 1e-10mm를 추가합니다. 지정 홀 회피 여유를 줄이지 않습니다.
- 위 수치는 이 독립시험의 계산 예산입니다. 회사의 가공 공차나 제품용 기준이 아닙니다.
- 엄밀한 방향 반올림을 적용한 구간 산술은 아닙니다. 모든 수치 오차를 수학적으로 보증하는 구현이 아닙니다.
- 작성 환경에서는 FontTools의 별도 SVG 파서와 94개 경로의 선분·곡선 해석을 대조해 일치했습니다.
  이 교차 확인은 개발 환경에서만 수행했으며 사용자 실행에는 FontTools를 요구하지 않습니다.

주요 검사 사례
- H의 빈 부분, O의 내부 빈 부분, 글자 사이 공백은 사각형이 겹쳐도 통과.
- 아주 작은 회피 원이 글자 획 내부에 놓인 경우도 침범으로 판단.
- 회피 원이 글자 전체를 덮는 경우, 곡선 중간을 침범하는 경우 탈락.
- 경로 없음·지원하지 않는 명령·판정할 수 없는 접촉은 unknown으로 보고.
- 원문에서 문제가 된 글자 위치를 함께 반환. 문자 인덱스는 0부터 시작하는 [시작,끝)입니다.

이번에 하지 않은 것
- 기존 배치의 수정, 자폭 후보 탐색, 줄바꿈 선택·점수 변경.
- 기존 사각형 기반 자폭 제한의 제거, 엔진의 정식 검사 교체.
- DXF 출력, Type3 외곽 일치 검증, 실제 폰트 파일 재로딩.
- 둥근 명판 외곽·텍스트 영역·테두리·장식·단선체·회전·가공 공구 궤적 검사.
- 기존 저장 작업의 승인 상태나 파일 버전 변경.

파일

results.json: 요약과 자동 검사 결과
audit.json: 300영역별 검사 결과
preview.html: 요약, 차이를 보여주는 6개 도형, 판정 불가 2건
