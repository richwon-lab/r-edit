리치원 명판별 결과·실패이유 연결시험 v0.1

사용
1. 압축을 모두 푼 뒤 preview.html을 브라우저에서 열어 결과를 확인합니다.
2. Python 3.10 이상으로 experiment.py 실행. 외부 패키지 설치는 필요 없습니다.
3. 결과는 스크립트 옆 results.json / annotated_results.json / diagnostic_examples.json / preview.html에 생성됩니다.
4. 자동 검사를 모두 통과하면 종료 코드 0입니다.

변경
- 기존 배치·공간검사 분리시험의 복사본에 이유 전달만 연결했습니다.
- RegionProbe.fit에서 검사한 후보의 상태와 이유를 기록합니다.
- 같은 문구의 여러 후보에서 관찰된 이유를 코드·대상·검사 단계별로 합칩니다.
- 한 후보에서 같은 이유가 반복되어도 같은 대상에는 한 번만 셉니다.
- 각 이유는 후보 수와 최대 3개의 재현 예시를 포함합니다. 후보 순서가 바뀌어도 요약은 같습니다.
- 참고 탐색의 기록은 정상 탐색과 구분해서 남깁니다.
- 기존 참조 함수의 반환에 diagnostics를 추가하고, reporting.py에서 명판·영역 결과에 연결합니다.
- 문구에 측정 자료가 없는 문자가 있으면 후보 생성 전에 계산 불가로 분류합니다.
- NO·RAT에서 정상 배치를 찾지 못한 예외도 결과로 반환해 다른 영역의 결과를 보존합니다.

상태
normal: 정상 배치
reference_only: 참고 결과와 기존 경고
no_normal_in_search / no_reference_in_search: 현재 탐색 범위에서 배치를 찾지 못함
calculation_unavailable: 문구 또는 측정 자료 문제로 계산할 수 없음
search_incomplete: 탐색 한도에 도달해 완료하지 못함

결과
- 기존 100행·300영역의 선택 배치·좌표·크기·자폭·점수·상태·경고가 모두 동일합니다.
- 정상 99행과 MCB46의 7줄·2.35mm 참고 결과를 유지합니다.
- 정상 결과에서 다른 후보의 탈락은 추가 확인 경고를 만들지 않습니다.
- 실제 발주에서 확인이 필요한 명판은 기존 MCB46 하나입니다.
- 글꼴 측정 자료 누락, NO 공간 부족, 참고 탐색 미완료는 별도 시험 입력으로 확인했습니다.
  실제 발주 데이터를 바꾸거나 이 사례를 실제 목록에 섞지 않았습니다.

기록의 의미와 한계
- 이유는 실제로 fit 검사를 거친 후보에서 관찰한 내용입니다.
- 참고 탐색에서 후보 생성 전에 제외한 가지 전체를 기록하지는 않습니다.
- 따라서 '검사한 후보에서 관찰된 이유'로 표시하며, 배치 불가능의 수학적 증명이나 원인 순위로 해석하지 않습니다.
- 후보 하나에서 서로 다른 이유가 발생할 수 있으므로 이유별 후보 수 합계가 탈락 후보 수와 다를 수 있습니다.
- 동일 문구의 후보 캐시를 재사용할 때 기록을 다시 늘리지 않습니다. 수량·주문 행 수가 아니라 검사한 후보 수입니다.
- 원문 인덱스는 Python 문자열의 0부터 시작하는 [시작,끝) 범위입니다.
- 홀 대상은 현재 디자인의 holes 배열 인덱스입니다.

유지한 범위
- 줄 전체 사각 범위와 디자인에 지정한 홀 여유를 사용합니다.
- 글자 내부·공백 사이에 홀을 끼워 넣는 윤곽 최적화는 포함하지 않습니다.
- 기존 배치 정책·점수·줄바꿈·자폭 탐색·글자 크기 환산을 바꾸지 않았습니다.
- 기존 제품 엔진이나 고객 설정은 변경하지 않았습니다.
- DXF 출력, 디자인 편집 UI, 화면에서 오류 부위를 선택하는 기능은 이번 범위 밖입니다.
- 미리보기는 결과 전달 확인용 보고서이며 완성된 제품 화면이 아닙니다.

파일

source_manifest.json: 복사 전 원본 파일 해시

preview.html: 결과 미리보기
