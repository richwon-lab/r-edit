리치원 패턴 수정·삭제 영향 확인 시험 v0.1

실행
  cd pattern_lifecycle_v01
  python experiment.py
필요한 경우: python -m pip install -r requirements.txt
결과: results.json / preview.html / lifecycle_previews.json / saved_*.json / DXF/
이미 DXF 폴더가 있으면 다음 실행은 DXF_02, DXF_03 등에 출력합니다.

현재 작업 안의 패턴만 다룹니다.
1. 기존 100행 / 300영역을 재현하고 R028에 단발성 수동 4줄·수량 2부를 적용합니다.
2. MONITORING / PANEL 두 줄 규칙을 명시적으로 등록합니다.
3. 같은 문구를 한 줄로 묶는 규칙으로 수정할 때 변경 전후를 확인합니다.
4. 적용하면 규칙과 계산 결과를 함께 반영합니다. 취소하면 현재 작업을 유지합니다.
5. 삭제는 선택한 규칙을 제거하고 현재 입력으로 자동 배치를 다시 계산합니다.
6. 저장·재열기·후속 문구 수정·DXF 출력으로 결과를 확인합니다.

유지하는 원칙
- 수동 R028은 자동 계산 대상에서 제외합니다. 다른 명판에 수동 배치를 전파하지 않습니다.
- 수정·삭제는 다른 등록 패턴을 유지합니다. 기존 규칙과 같은 수정은 변경을 만들지 않습니다.
- 수정은 같은 패턴 문구의 줄 구성만 대상으로 합니다. 패턴 문구 자체 변경은 지원하지 않습니다.
- 규칙이 충돌하여 현재 탐색에서 후보를 확보하지 못하면 변경을 적용하지 않습니다.
- 모두 수동인 문구의 패턴 삭제는 규칙만 지우고 수동 결과를 그대로 유지합니다.
- 미리보기 이후 다른 변경이 적용되거나 수량이 바뀌거나 작업을 다시 열면 새 확인이 필요합니다.
- 원문 문자·공백·순서, 커터·홀 검사·점수, 정상/참고 구분을 유지합니다.

삭제와 되돌리기는 다릅니다.
삭제는 현재 문구와 현재 자동 대상에 맞춰 다시 계산합니다. 이전 문구를 복원하지 않습니다.
수동으로 바뀐 명판은 자동 그룹에서 제외되므로, 삭제 후 배치가 과거 배치와 같다는 보장은 없습니다.
R027의 INLET를 INLET1로 바꾼 뒤 규칙을 삭제해도 INLET1은 유지됩니다.

실제 DXF 비교
01_Registered: MONITORING / PANEL 두 줄 규칙 등록
02_Updated: MONITORING PANEL 한 줄 규칙으로 수정
03_Deleted: 규칙 삭제 후 현재 자동 조건으로 재계산
04_DeletedAfterTextEdit: INLET1 수정 후 규칙 삭제
각 폴더는 정상/참고 R2000 편집 가능 TEXT 파일과 출력 내역을 포함합니다.

범위 밖
실제 UI, 패턴 문구 변경, 고객사·프로젝트 간 공유, 자동 패턴 추론,
일반 충돌 해결, 수동 원문 교체, 새 디자인·형상, 생산 적용.
preview.html은 변경 전후를 보여주는 정적 시험 결과입니다.
수량은 시험값이며 동시 사용자·클라우드 충돌을 다루지 않습니다.
기존 생산 프로그램과 원본 저장 파일은 변경하지 않습니다.
