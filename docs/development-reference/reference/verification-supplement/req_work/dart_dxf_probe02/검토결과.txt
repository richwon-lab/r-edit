리치원 Dart DXF 기술 검증 02 — 2026-10-03

이번 결정
Flutter를 제품의 화면 기반으로 채택하는 방향이다. 도안 데이터와 자동 배치 로직은 Dart 구현을 우선한다. Python은 제품의 필수 구성으로 두지 않는다. 구체적으로 확인된 구현 부담이 큰 경우에만 제한적으로 재검토한다.
이번 Python 코드는 독립적인 결과 검사용이며 Dart 시험 프로그램 실행에는 필요하지 않다.

목적
이전 검증에서 발견된 Dart dxf 3.1.3의 문제가 국소적인 보완으로 해결 가능한지 확인한다. 완성된 편집기, DXF 가져오기 전체 또는 성능을 검증하는 단계는 아니다.

변경 사항
배포 원본을 복사한 별도 시험 폴더에서 2개 파일만 수정했다. changes.patch에 전체 차이를 기록했다.
1. ac_db_polyline.dart
   기존 꼭짓점 좌표를 원래 태그 위치에서 갱신하도록 변경했다. 곡선 계수와 꼭짓점별 선 폭을 다른 좌표와 분리하지 않는다.
   이번 구현은 꼭짓점 수를 유지한 XY 좌표 변경만 허용한다. 꼭짓점 추가/삭제는 변경을 적용하기 전에 명시적으로 거부한다. 곡선 형태의 임의 변형, 비균일 확대, 전체 CAD 변환을 해결한 것은 아니다.
2. ac_db_text.dart
   setBaselineCenter를 추가했다. 기존 문자 스타일 참조, 자폭, 수평 중앙/수직 기준선 정렬, 정렬 좌표를 지정한다.
   기존 값은 갱신하고 없는 DXF 태그는 적절한 AcDbText 하위 클래스 위치에 추가한다. 반복 지정해도 동일 태그를 중복 추가하지 않는다.
   폰트 파일 설치/탐색, 새 STYLE 생성, 모든 정렬 유형, 실제 글자 외곽 중심 보정까지 구현한 것은 아니다.

실행 결과
Dart 3.6.2에서 읽기·수정·출력을 실행했다. Python ezdxf 1.4.4는 별도 검증기로만 사용했다.
- 사용자 DXF 6개와 합성 도면 1개의 무수정 읽기/저장 확인: 통과.
- 위 7개 파일의 모든 LWPOLYLINE 좌표를 X+1, Y+2 이동: 예상 좌표와 기존 곡선 계수·선 폭·기타 태그 유지.
- 이동 대상 이외의 모델 공간 객체: 비교한 DXF 태그 유지.
- DXF 버전, 문자 스타일 속성 유지.
- 저장 결과 audit에서 오류/자동 보정 발생 없음.
- 텍스트 스타일 HY_TEST → H2GTRL.TTF 참조, 높이 4.5, 자폭 0.8, 수평 중앙, 기준선 좌표 (16,11,0) 확인.
- U, 한글, 베트남어가 포함된 시험 문구의 DXF Unicode escape를 별도 해독했을 때 원문과 일치.
- 텍스트는 TEXT 객체 유지. 윤곽선으로 변환하지 않았다.
- 문자 배치를 두 번 조정해도 관련 태그 중복 없음.
- 허용하지 않는 꼭짓점 수 변경이 거부되고 원본 상태 유지됨을 확인.
verification.json에는 448개 세부 비교가 기록되어 있다. 448종 도면이나 448개 사용 시나리오를 검증했다는 뜻은 아니다.

중요한 한계
- Flutter UI 및 Windows/Type3에서 실행하거나 육안 확인한 결과가 아니다.
- 글자 높이 4.5라는 DXF 속성값 검증이다. 실제 인쇄/조각 글자 외곽이 4.5mm인지, 중앙에 시각적으로 놓이는지 검증하지 않았다.
- 한글/베트남어 문구의 정보 보존과 해당 폰트/Type3의 글리프 지원은 다르다. 실제 표시 성공을 보장하지 않는다.
- 기존 DXF의 레거시 바이트를 latin1로 임시 대응하여 원래 바이트로 되돌렸다. CP949 문자를 UI에 올바르게 디코딩하는 구현이 아니다. 시험 문구는 Dart에서 ASCII Unicode escape로 기록했다. 제품용 인코딩 처리는 아직 남아 있다.
- R2000/R2004 원본을 읽어 수정 후 그 버전을 유지했다. 새 R2000 문서를 처음부터 만드는 기능을 이번에 검증하지 않았다. DXF.create() 기본 버전은 원본 그대로 R2007이다.
- 이번 수정은 자체 라이브러리 사본에 대한 시험 수정이다. dxf 공식 배포가 수정된 것이 아니다. 특정 라이브러리의 최종 채택이나 전체 호환성 보증도 아니다.
- 블록, 스플라인, 임의 외부 DXF 확장 정보 등의 표시·편집 지원 전체를 다루지 않았다.

판단
앞서 발견된 곡선 좌표 갱신 결함과 문자 배치 속성 부족은 이번 범위에서 국소적인 Dart 수정으로 보완할 수 있었다. 따라서 이 두 문제를 근거로 Python을 제품 필수 구성으로 둘 필요는 없다.
남은 핵심은 실제 글자 치수·정렬 일치와 지원할 DXF 범위의 입출력 완결성이다. 기능 검증 결과를 성능 검증으로 확대 해석하지 않는다.

재현
  dart probe.dart
  python verify.py
첫 명령은 Dart SDK만 필요하다. package/lib를 상대 경로로 직접 가져와 pub get은 필요하지 않다.
두 번째는 독립 검증용이며 ezdxf 1.4.4가 필요하다.
sources는 입력 복사본, outputs는 시험 출력물이다. 생산 승인 파일이 아니다. 폰트 파일은 묶음에 포함하지 않았다.
