# Type3 줄바꿈 가져오기 간단 시험

목적: 하나의 DXF TEXT 객체에 넣은 기호를 현재 사용하는 Type3가 줄바꿈으로 해석하는지 확인한다.
상태: 파일 생성, DXF 재읽기 및 구조 검사를 완료했다. 실제 Type3 가져오기는 실행하지 않았다.
실행 환경: Linux, ezdxf 1.4.4. 회사의 Windows Type3에는 접근하지 않았다.

## 시험 순서
1. 새 빈 Type3 문서에서 01_TEXT_checks_R2000.dxf를 직접 가져온다.
2. T01의 AAA BBB가 보이고 T02에서 AAA와 BBB가 두 줄로 보이는지 확인한다.
3. T03~T07이 두 줄인지, 기호가 그대로 보이는지, 문자가 사라졌는지 확인한다.
4. 두 줄이 된 항목은 텍스트 편집 모드에서 한 객체로 두 줄을 함께 수정할 수 있는지 확인한다.
5. 별도 빈 문서에서 02_MTEXT_reference_R2000.dxf를 가져와 비교한다.

CAD에서 다시 저장하거나 중간 변환 프로그램을 거치면 시험 기호가 달라질 수 있으므로 우선 원본 DXF를 직접 가져온다.
이 파일에는 명판 생산용 도안이나 NC 데이터가 없다. 글꼴 지정은 Arial, 높이는 4 mm, 단위는 mm다. 글꼴 파일은 포함하지 않는다.

## 항목
| 번호 | 파일 내부 표현 | 목적 |
|---|---|---|
| T01 | TEXT 1개: AAA BBB | 일반 한 줄 기준 |
| T02 | TEXT 2개: AAA / BBB | 기존 줄별 TEXT 기준 |
| T03 | TEXT 1개: AAA\PBBB | MTEXT의 문단 코드를 TEXT에서도 해석하는지 탐색 |
| T04 | TEXT 1개: AAA\nBBB | 역슬래시와 n이라는 두 글자를 해석하는지 탐색 |
| T05 | TEXT 1개: AAA^JBBB | 캐럿 표기를 해석하는지 탐색 |
| T06 | TEXT 1개: AAA\U+000ABBB | 이스케이프된 LF 코드의 해석 탐색 |
| T07 | TEXT 1개: AAA\U+000DBBB | 이스케이프된 CR 코드의 해석 탐색 |
| M01 | MTEXT 1개: AAA\PBBB | 표준 다중행 표현 비교 |

T03~T07은 지원을 보장하지 않는 탐색용 입력이다. 실제 개행 바이트를 ASCII DXF의 문자열 행에 직접 넣은 시험은 아니다.
TEXT는 일반적으로 단일 행을 나타내고, \P는 MTEXT의 문단 코드다. 이 사실만으로 구형 Type3의 가져오기 동작을 단정할 수 없다.
M01은 TEXT 시험과 섞지 않았다. MTEXT 가져오기 실패가 다른 TEXT 시험을 방해하지 않게 별도 파일로 둔다.

## 결과를 알려줄 때
가져온 전체 화면과 아래 항목만 알려주면 된다.
- Type3 버전과 가져오기 설정 중 텍스트 관련 옵션
- T01/T02 정상 여부
- T03~T07에서 두 줄로 보인 번호
- 두 줄인 경우 텍스트 편집 시 한 객체인지 여러 객체인지
- M01의 표시와 편집 가능 여부

두 줄로 보이는 것만으로 성공 판정하지 않는다. AAA와 BBB의 보존, 편집 가능, 객체 수, 글자 높이와 줄 위치를 확인한다.
한 객체 다중행이 되더라도 줄마다 다른 자폭을 유지할 수 있는지는 다음 별도 시험 대상이다.
이번 시험이 실패해도 기존의 줄별 TEXT 출력 대안은 유지한다.

## 로컬 확인 범위
- DXF R2000 형식으로 저장하고 ezdxf로 다시 읽었다.
- 감사에서 구조 오류와 자동 수정 항목이 0건임을 확인했다.
- 저장된 group 1 문자열에 각 탐색용 표기가 실제 포함됨을 확인했다.
- 이것은 Type3 호환성 판정이 아니다. 로컬 기록은 local_structure_check.json에 있다.
