리치원 규칙 연결 독립시험 v0.2

실행
1. ZIP을 새 폴더에 압축 해제합니다.
2. Python 3.10 이상으로 experiment.py를 실행합니다.
   python experiment.py
3. 같은 폴더의 preview.html을 브라우저에서 엽니다.

별도 pip 설치, 폰트 설치, 인터넷 연결은 필요하지 않습니다.
실제 배치 계산은 기존 v0.6 엔진과 동봉된 HY세고딕 측정값을 사용합니다.
Python 시험 코드이며 Flutter 또는 최종 엔진 구현 언어를 결정하지 않습니다.

이번에 확인할 것
- 16개 검사 모두 true, passed 16 / total 16.
- 기본 자폭: 리치원 80% → 고객사 90% → 고객사 설정 해제 후 80%.
  90%는 기본값입니다. 홀 회피 때문에 실제 자폭은 더 작을 수 있습니다.
- FEEDER / PANEL 등록 패턴 제외 시 실제 줄바꿈 변경.
- 긴 문구의 선호 줄 수를 6에서 3으로 바꿨을 때 검토용 결과·경고 표시.
- NO·RAT, 홀, 정렬, 텍스트 영역 및 다른 디자인에 변경 전파 없음.
- 저장 당시 결합값·출처·배치가 공통 기준 변경 이후에도 유지됨.

시험 데이터
기존 36×36 시험의 100개 결과와 완전히 같은지 먼저 비교합니다.
조건 변경은 실제 문구 3개와 시험용 긴 문구 1개로 확인합니다.
80%/90%, 3줄 제한은 가상 변경입니다. 실제 고객 기준 수정이 아닙니다.
미리보기는 규칙 연결을 비교하는 보고서이며 제품 UI 시안이 아닙니다.
DXF를 생성하지 않으므로 이번에는 Type3 확인이 필요하지 않습니다.

지원 범위
본문 영역의 기본 자폭, 선호 줄 수, 기존 등록 패턴 적용/제외를 연결합니다.
일반 규칙 강도/곡선, 규칙 전체 끄기, 새 폰트, 인쇄, 커터 기준 변경,
임의 신규·중첩 패턴 또는 패턴 내부 줄바꿈 변경은 연결하지 않습니다.
미지원 설정은 조용히 무시하지 않고 오류로 알립니다.
이 제한은 이번 시험 연결기의 범위이며 최종 제품의 지원 범위 결정이 아닙니다.
기존 배치 엔진은 변경하지 않았습니다.

파일
experiment.py         전체 실행 및 검사
bridge.py             규칙 결합 → 기존 엔진의 입력 변환
rules.py              이전 v0.1 규칙 결합 모듈 (변경 없음)
engine_v06.py 등      기존 배치 및 저장 시험 코드 (변경 없음)
fixture_v06.json      100개 기존 결과, 디자인, 시험 정책
font_metrics.json     HY세고딕 사전 측정 자료
results.json          검사 결과와 비교 사례의 실제 배치 좌표
resolved_rules.json   사례별 최종 값과 출처
preview.html          실제 글자 윤곽으로 그린 비교 보고서
saved_rules_r1.json   80% 기준으로 저장된 독립 시험 작업

반복 실행 시 이 폴더의 위 네 가지 결과 파일은 덮어씁니다.
다른 폴더나 기존 프로그램·고객 도안 파일은 읽거나 변경하지 않습니다.
saved_rules_r1.json의 재계산에는 당시 엔진과 글꼴 측정값을 사용합니다.
저장 당시 결합 완료된 디자인/정책을 사용하며 현재 공통 규칙을 다시 합치지 않습니다.
Google Drive 동기화·공유 충돌·실제 가공 품질은 시험하지 않습니다.
표시 시간은 여러 검사·저장·별도 프로세스 실행을 합한 전체 시간입니다.
