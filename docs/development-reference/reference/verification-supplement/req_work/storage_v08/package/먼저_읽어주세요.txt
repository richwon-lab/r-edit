리치원 저장·재현 독립 시험 v0.8

실행 방법
1. 압축을 풉니다.
2. experiment.py를 실행합니다. 추가 라이브러리 설치는 필요 없습니다.
3. 결과의 assertions가 모두 true인지 확인합니다.
4. preview.html에서 저장 당시 / 다시 열기 / 새 기준 적용 결과를 비교합니다.

시험의 목적
공용 기준이 바뀌어도 과거 작업이 변하지 않아야 합니다.
당시 작업의 입력, 적용된 디자인·규칙, 글꼴 측정값, 배치 결과를 함께 저장합니다.
공용 기준 ID는 출처를 표시하는 용도이며 다시 열 때 최신 값을 가져오지 않습니다.

중요한 구분
- 다시 열기: 저장된 결과를 그대로 사용. 배치 엔진을 불러오거나 재계산하지 않습니다.
- 당시 조건으로 재계산: 저장된 조건과 이 시험의 동일한 엔진으로 계산합니다.
- 새 기준 적용: 변경된 조건으로 새 결과를 만들고 별도 기록으로 저장합니다.
  과거 기록을 덮어쓰지 않습니다.

이번 시험
- v0.6의 100개 결과를 저장 후 다시 읽습니다.
- 별도의 Python 프로세스에서도 동일하게 읽는지 확인합니다.
- 시험용 공용 본문 자폭을 70%에서 80%로 바꿉니다.
- 과거 작업을 다시 열었을 때 70% 기준 결과가 유지되는지 검사합니다.
- 당시 조건으로 실제 재계산하여 기존 100개 결과와 정확히 비교합니다.
- 새 기준을 직접 적용한 경우에만 별도 r2 결과를 저장합니다.
- NO·RAT 조건과 배치, 외형·홀·영역은 유지합니다.
- MCB46의 검토 필요 상태와 커터 경고도 함께 보존합니다.

70% → 80%는 보존 동작을 확인하기 위한 가상 변경입니다.
실제 고객 기준 변경이 아니며 80% 결과가 더 좋다는 의미도 아닙니다.
이번 시험에서는 홀 회피 간격을 변경하지 않았습니다.

파일
- saved_job_r1.json: 당시 조건과 결과를 보존한 작업.
- saved_job_r2.json: 새 기준을 명시적으로 적용한 별도 결과. r1과 연결된 이력 포함.
- results.json: 검사 결과와 변경된 명판 번호.
- preview.html: 일부 변경 사례와 MCB46의 전후 비교.
- fixture_v06.json: 기준이 된 입력·디자인·규칙·기존 결과.
- font_metrics.json: 기존 HY세고딕 측정값. 실제 폰트 파일은 아닙니다.
- source_design.dxf: 보관용 원본 외형. 이번에는 DXF를 새로 생성하지 않습니다.
- engine_v06.py / baseline_v02.py / regions_v05.py: 기존 독립 시험의 엔진 코드.
  직접 실행하지 않고 experiment.py만 실행하세요.

방어 검사
- 당시 엔진이 없거나 달라졌으면 재계산을 거부하지만 저장 결과는 열 수 있습니다.
- 글꼴 측정값이 바뀌면 재계산을 거부합니다.
- 저장 내용 변조·손상 또는 지원하지 않는 저장 형식을 감지합니다.
- 파일 교체 직전에 시험용 오류를 발생시켜 이전 저장본이 유지되는지 확인합니다.
  정전·장치 고장·네트워크 드라이브의 원자성까지 증명한 것은 아닙니다.

현재 한계
- 로컬 단일 작업자 시험이며 최종 저장 구조를 확정한 것이 아닙니다.
- Google Drive 동기화 충돌, 여러 PC의 동시 수정, 서버·DB 선택은 포함하지 않습니다.
- 원본 폰트 파일을 불러오는 시험이 아니며 저장된 측정값으로만 재계산합니다.
- 재계산에는 보관된 동일 엔진이 필요합니다. 엔진 버전 이름만 저장하면 충분하다는 의미가 아닙니다.
- 이번 표본에는 수동 줄바꿈 변경, 과거 기록을 조회하는 규칙, 전체 레이어 결합 과정은 없습니다.
- Type3에서 최종 수정한 도안은 추적하지 않습니다.
- 이번 결과는 시험용이며 실제 생산 승인이나 자동 승인을 의미하지 않습니다.
