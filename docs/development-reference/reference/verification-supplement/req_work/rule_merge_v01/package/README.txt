리치원 규칙 결합 독립 시험 v0.1

실행
1. ZIP 전체를 한 폴더에 풉니다.
2. Python 3.10 이상으로 experiment.py를 실행합니다. 외부 패키지 설치는 없습니다.
3. 같은 폴더의 preview.html을 브라우저로 엽니다.

결과
- results.json: 14개 검사와 상세 근거
- resolved_rules.json: 최종 설정값, 적용 출처, 패턴 목록
- preview.html: 결과 확인 화면. 제품 UI 시안은 아닙니다.
출력 파일은 실행할 때 같은 폴더에서 갱신됩니다.

범위
v0.12 설계 검토 문서의 규칙 결합 중 독립적인 부분만 시험합니다.
배치 엔진, 원래 주문, DXF, 과거 시험 결과, 공용 기준을 수정하지 않습니다.
Python은 독립 시험에 사용하며 제품 엔진 언어를 결정하지 않습니다.
Windows 실행을 목표로 경로를 파일 위치 기준으로 처리했고 표준 라이브러리만 사용합니다.
사용자 PC에서의 실행은 별도 확인이 필요합니다.

시험용 선택
- 명시적 순서 목록에 모든 레이어 ID를 한 번씩 기록합니다. 전달 순서와 분리합니다.
- 미지정은 키 생략, 기능 끄기는 false입니다. null은 허용하지 않습니다.
- 같은 규칙 ID를 한 번만 실행 목록에 넣습니다. 실제 감점은 계산하지 않습니다.
- 패턴은 미리 지정한 ID로 수정합니다. 역할과 문구는 같은 ID 아래서 바꾸지 않습니다.
- 같은 문구의 다른 역할은 보존합니다. 같은 역할·문구가 다른 ID로 등록되면 오류입니다.
  이 중복 처리 정책과 ID 형식은 제품의 최종 등록 방식을 확정하지 않습니다.
- 기능을 끄면 실행 규칙 목록에서 빠지며 패턴 목록 자체는 보존합니다.
  enabled_pattern_ids는 항목 자체의 사용 설정 목록이며 기능 실행 여부는 active_rule_ids를 함께 봐야 합니다.
- 줄 예시는 보통 공백 경계의 FEEDER PANEL 사례만 다룹니다.
  전체 원문·임의 공백·괄호 앞 개행의 저장 표현은 별도 설계 및 시험 대상입니다.
- 조각의 기준 커터 필드는 이 시험에서 필수입니다. 인쇄에서는 적용하지 않습니다.
  커터를 자동 선정하거나 실제 가공 가능성을 검사하는 시험은 아닙니다.
- 필수 공간 조건은 덮어쓰기 대상에서 제외합니다. 실제 형상 검사는 하지 않습니다.
- 폰트는 이름만 사용합니다. 글꼴 설치·인식·측정은 확인하지 않습니다.
- 90%와 선호 1~6줄은 합성 결합 사례이며 어떤 고객사 규칙도 바꾸지 않습니다.

검증되지 않는 항목
패턴 매칭과 포함 관계의 실제 배치 선택, 후보 보존, 동점, 탐색 종료,
Type3, 수량, 저장 파일 재현, 공동 편집, 사용자 UI.
기존 v0.1~v0.10의 통과 범위를 새 규칙 구현의 검증으로 확대하지 않습니다.
