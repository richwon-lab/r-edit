리치원 수정·배치·출력 상태 관리 독립 시험 v0.9

실행
1. 압축을 풉니다.
2. experiment.py를 실행합니다. 추가 설치는 필요 없습니다.
3. assertions가 모두 true인지 확인합니다.
4. preview.html을 열어 대표 흐름과 전후 배치를 확인합니다.

이번 목표
문구만 수정했는데 이전 배치가 그대로 출력되는 실수를 막습니다.
입력 수정은 계산을 시작하지 않습니다. 배치 버튼에 해당하는 요청을 할 때 계산합니다.
현재 입력에 해당하는 최신 요청 결과만 적용합니다.

동작
- 수정 전: 저장된 배치 사용 가능. 정상 결과와 검토용 결과를 구분합니다.
- 문구 수정: 기존 미리보기 유지 + 배치 갱신 필요. 이전 결과 출력 차단.
- 배치 버튼: 그 시점의 문구와 적용 기준을 복사하여 계산 요청.
- 계산 중 재수정: 이전 계산 결과는 도착해도 적용하지 않음. 다시 배치해야 함.
- 계산 완료: 현재 입력과 최신 요청이 모두 맞는 결과만 적용.
- 계산 취소: 취소한 결과는 뒤늦게 도착해도 적용하지 않음.
- 계산 실패: 이전 화면을 보존하지만 출력은 차단. 재실행하여 복구.
- 출력 준비 뒤 수정: 이전 출력 요청은 쓰지 않음. 새 배치 후 다시 출력 요청.

시험에서 확인하는 것
- 기존 100개: 정상 99개 / 검토용 MCB46 1개를 구분 유지.
- NO만 바꿨을 때 본문과 RAT 배치 유지.
- 이전 계산이 새 계산보다 늦게 도착해도 최신 결과 유지.
- 이전 오류가 늦게 도착해도 현재 상태 유지.
- 문구를 A → B → A로 되돌려도 이전 요청을 자동 적용하지 않음.
  이 시험은 단순하고 보수적으로 다시 배치를 요구합니다. 최종 되돌리기 UX는 별도입니다.
- 같은 입력으로 두 번 요청해도 마지막 요청만 적용.
- 적용 기준 변경도 이전 배치를 갱신 필요 상태로 전환.
- 다른 작업의 계산 결과나 요청 문구와 다른 결과 거부.
- 출력 준비 후 문구가 바뀌면 기존 출력 파일을 덮어쓰지 않음.
- 새 배치 후에도 이전 출력 요청은 거부하며, 새 출력 요청만 허용.

- engine_v06.py / baseline_v02.py / regions_v05.py: 기존 배치 시험 엔진. 직접 실행하지 마세요.

검증 범위
- 이번 시험은 기존 배치 엔진으로 실제 계산한 결과를 사용합니다.
- 완료 통지 순서를 의도적으로 바꿔 전달하는 방식입니다.
  실제 여러 스레드나 Flutter UI에서 동시에 실행한 시험은 아닙니다.
- 계산 취소는 결과 반영을 막는 동작입니다. CPU 계산 자체를 중단시키는 기능은 아닙니다.
- 출력 직전 검사는 JSON 파일 쓰기로 확인했습니다.
  기존 v0.7 DXF 출력기에 연결한 전체 시험은 아직 아닙니다.
- 전체 디자인 묶음을 재계산합니다. 일부 행만 재계산하는 최적화는 적용하지 않았습니다.
- 여러 디자인 동시 편집, 수량, 수동 줄바꿈, 프로그램 재시작 중인 작업,
  Google Drive 동기화 충돌은 이번 범위에 포함하지 않습니다.
- 배치 갱신과 예외 승인 여부는 별개입니다.
  MCB46은 최신 배치여도 검토용이며, 정상 생산 결과로 자동 승인되지 않습니다.
- 실행 시간은 여러 시나리오 계산을 합친 전체 시험 시간입니다.
  한 번의 배치 버튼 응답 시간 또는 Flutter 성능을 뜻하지 않습니다.

실제 고객 기준, 홀 간격, 줄바꿈 알고리즘은 바꾸지 않았습니다.
명판 NO와 자폭 70% → 80% 변경은 상태를 확인하기 위한 가상 시험입니다.
