# 리치원 후보 보존 독립 시험 v0.2

## 실행

ZIP을 모두 풀고 `experiment.py`를 실행합니다. 이전 시험처럼 PyCharm에서 실행하거나 아래 명령을 사용하면 됩니다.

```text
python experiment.py
```

Python 3.9 이상. 추가 패키지 설치와 인터넷 연결은 필요 없습니다.
실행 파일 옆에 `results.json`과 `preview.html`이 생성됩니다. `preview.html`을 브라우저로 열면 명판 모양과 선택된 줄바꿈을 확인할 수 있습니다. 동봉된 두 결과 파일은 개발 환경에서 먼저 실행한 결과이며, 재실행하면 현재 PC의 결과로 덮어씁니다.

## 이번에 확인하는 것

앞선 v0.1은 미리 만든 가상 후보를 비교했습니다. 이번에는 실제 발주 문구에서 줄바꿈 후보를 생성하고, 실제 HY세고딕의 글자별 측정 자료로 크기·자폭·영역·홀 회피를 검사합니다.

엠알씨이 3448 BCC의 기존 추출 자료 286행 중 9개 문구를 사용합니다. 패턴 3종마다 3개씩이며, 원본 행 번호는 `input.json`에 있습니다. 이번 입력은 전체 발주가 아닙니다.

| 방식 | 의미 |
|---|---|
| `all` | 생성된 모든 후보 조합을 비교 |
| `signature` | 다른 명판과의 비교에 같은 영향을 주는 후보끼리 묶고, 그 안에서 가장 좋은 후보를 보존 |
| `top2` | 명판 각각의 점수가 좋은 후보 2개만 보존하는 비교용 방식 |

전체 비교와 `signature` 방식은 최종 비용과 선택한 줄바꿈이 모두 일치해야 합니다. 입력 순서와 후보 순서를 뒤집어도 같아야 합니다. 모든 후보에 대해 원문 문자 보존, 영역 안 배치, 홀 회피, 글자 크기와 자폭 제한을 검사합니다.

## 시험 조건 — 전체 제품에 적용할 기본값이 아님

- 75×25mm, 중앙 중심 정렬, HY세고딕.
- 글자 크기 4.5mm 우선, 1~3줄. 그 크기로 유효 후보가 없을 때만 0.05mm씩 낮추며 3mm까지 검사합니다.
- 기본 자폭 80%, 하한 58%. 하한을 완화하거나 3mm 미만의 다른 커터 구간으로 넘어가지 않습니다.
- 텍스트 영역: 왼쪽 아래 (2, 2), 오른쪽 위 (73, 23)mm.
- 홀 중심 (4, 12.5), (71, 12.5)mm. 홀 반지름 2mm, 회피 반지름 6mm.
- 회피 반지름은 앞선 시험에서 사용한 가정(머리 지름 8mm + 추가 여유 2mm)입니다. 실제 도안의 확정값이 아닙니다.
- 줄의 기준선 간격은 글자 크기 + 1.2mm입니다. 이 값도 시험 조건입니다.
- 이번 시험은 정상 후보 보존을 확인합니다. 정상 후보가 없으면 이유와 함께 중단합니다. 제품에서 필요한 참고 배치·경고는 아직 구현하지 않았습니다.

## 폰트와 미리보기

`font_metrics.json`은 제공된 H2GTRL.TTF(HY세고딕)에서 미리 추출한 영문·기호의 advance, 경계, 윤곽입니다. 원래 폰트 파일은 포함하지 않습니다. 미리보기에는 이 윤곽을 사용하므로 PC에 해당 폰트가 설치되지 않아도 보입니다.

폰트 측정값의 출처 해시는 파일에 기록했습니다. 대문자 H의 실제 높이를 기준으로 mm를 환산합니다. Type3의 글자 크기 정의와의 일치는 별도 검증 대상입니다. 문자쌍 커닝·복합문자 처리와 폰트 로딩은 이번 실행에 포함하지 않습니다. 측정 자료에 없는 문자는 대체 폰트로 넘어가지 않고 명시적으로 중단합니다.

미리보기의 회색 점선은 텍스트 영역, 빨간 원은 홀 회피 영역입니다. 글자 윤곽의 경계 상자로 충돌을 검사하므로 글자 내부 빈 공간까지 활용하는 정밀 곡선 충돌과는 다릅니다. 이 HTML은 시험 보고서이며 제품 UI 제안이나 생산용 도안이 아닙니다.

## 패턴 보존 범위

패턴 내부의 줄바꿈 위치뿐 아니라, 패턴 앞뒤에 다른 문구가 같은 줄에 붙어 있는지도 보존 기준에 포함합니다. 이번 비교에서 명판 사이의 점수는 오직 이 정보에만 의존합니다. 그래서 같은 보존 기준 내에서는 개별 점수가 더 낮은 후보를 안전하게 제외할 수 있습니다. 비용은 낮을수록 좋습니다.

향후 다른 명판과 글자 크기·자폭 등을 직접 비교하는 규칙이 추가되면 보존 기준도 함께 확장해야 합니다. 이 시험만으로 모든 미래 규칙에 안전하다는 결론을 내리면 안 됩니다.

`STOP P/B`, `EM'CY STOP P/B`, `NO.2 ECDIS`와 그룹은 시험 입력에 직접 지정했습니다. 자동 패턴 발견이나 중첩 패턴의 일반적인 우선순위를 구현한 것은 아닙니다. EM'CY 그룹은 긴 패턴만 직접 적용했습니다. 시험 점수는 후보 축소를 비교하기 위한 값이며 고객 승인된 미관 기준을 대체하지 않습니다.

## 시간 해석

- `generation_ms`: 줄바꿈 후보 생성, 글자 크기·자폭·홀 회피 계산 및 후보 검증 시간.
- `selection_ms`: 각 보존 방식의 후보 정리와 조합 선택 시간.
- `total_ms`: 입력 자료 로딩, 비교, 순서 역전 검사와 기본 방어 검사까지의 시간. 결과 파일 작성·미리보기 생성, Python 프로세스 시작 시간은 제외.

실제 폰트 측정은 미리 해두었으므로 측정 자체의 시간은 포함하지 않습니다. 캐시된 글자 측정 자료로 문자열 너비를 계산하는 시간은 후보 생성에 포함됩니다. 소규모 9문구 결과이며 수백 개 처리나 Flutter UI의 반응 속도를 보증하지 않습니다.

## 결과와 다음 판단

이번 환경의 3개 묶음 모두 전체 비교와 보존 후 선택이 일치했습니다. 조합 수는 2,178개에서 471개로 감소했습니다. 이 9개 문구에서는 상위 2개 방식도 일치했습니다. 앞선 v0.1에서 발견한 상위 2개 방식의 실패 사례가 해소되었다는 뜻은 아닙니다.

선택된 결과는 전부 4.5mm·80%였습니다. 따라서 최종 선택이 글자 크기 축소나 커터 경계에 걸리는 사례는 이번 9개로 검증하지 못합니다. 긴 문구에서 크기를 축소하는 경우와 디자인별 조건 차이는 다음 독립 시험으로 남깁니다.

생산용 엔진·DXF 출력·Type3 검증·자동 패턴 인식·참고 배치는 이번 범위 밖입니다. Python 사용은 독립 시험용이며 제품 엔진 기술을 확정하지 않습니다.
