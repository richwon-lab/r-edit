리치원 표시 글자 크기 확인 v0.1

먼저 01_FontSize_Check_R2000.dxf를 CAD와 Type3에서 열어주세요.
Python 실행이나 추가 설치 없이 확인할 수 있습니다. 생산용 도안이 아닙니다.

1. 글꼴이 HY세고딕인지 먼저 확인합니다. 다른 글꼴이면 치수 비교는 보류합니다.
2. P01의 H를 선택했을 때 글자 크기가 4.5인지 확인합니다.
   P02~P05도 4.5, P06은 3.0입니다.
   자폭은 P01 100%, P02~P05 80%, P06 58%입니다.
3. 파란 사각형은 이전 시험의 H 외곽 높이 환산으로 예상한 글자 범위입니다.
   실제 가져온 검은 글자가 이 사각형의 상하좌우와 맞는지 봅니다.
   Type3에서 색상이 다르게 보이면 SAMPLE_TEXT와 OLD_MODEL_BOX를 구분합니다.
4. 전체 스크린샷과 P01의 표시 크기를 알려주시면 됩니다.
   맞지 않는 것이 보이면 해당 번호만 추가로 알려주세요.
   정확한 외곽 치수 측정은 꼭 해야 하는 작업은 아닙니다.

주의할 해석
- 문구가 바뀌면 실제 외곽 높이는 달라질 수 있습니다. 모든 상자가 높이 4.5는 아닙니다.
- P01/P02는 가로 배율만 다르므로 같은 글꼴이라면 세로 크기가 같아야 합니다.
- CAD와 Type3가 숫자 4.5를 유지하는 것과 외곽 크기가 서로 일치하는 것은 다른 검사입니다.
- 왼쪽/기준선 정렬만 사용하여 크기 문제와 중앙 정렬 문제를 분리했습니다.
- Type3 그룹 해제 후에도 샘플 문구는 TEXT이며 도형으로 깨지 않았습니다.
- DXF에 포함한 사각형과 선은 확인용입니다. NC 가공용으로 사용하지 않습니다.

파일
01_FontSize_Check_R2000.dxf : 표시값을 그대로 넣은 6개 샘플
preview.html : 기존 환산 모델로 그린 예상 모습. 외부 프로그램 실제 화면이 아님
expected.json : DXF 값과 기존 모델 예상 외곽 치수, 검증 상태
font_metrics.json : 기존 시험의 HY세고딕 ASCII 글리프 측정 자료. TTF 파일 아님
make_probe.py : 선택적인 재생성 코드(Python 3.10+, ezdxf 필요)

이번에 확인된 사실
기존 v0.7 출력 코드는 DXF TEXT 높이에 4.5 등의 값을 그대로 기록했습니다.
기존 미리보기와 공간 계산은 크기/H 형상 높이로 글리프를 환산했습니다.
따라서 출력 숫자를 임의 보정하지 않고 실제 가져오기와 그 환산이 맞는지 확인합니다.
기존 환산이 잘못됐다는 결론도, 맞다는 결론도 아직 내리지 않습니다.
커터 기준은 사용자 확인대로 CAD/Type3에 표시되는 글자 크기를 기준으로 합니다.

한계
HY세고딕 한 폰트의 일부 문자만 다룹니다. 커닝/복잡한 문자 조합, 모든 폰트,
중앙 정렬, 곡선 경계, 실제 가공 품질은 검증하지 않습니다.
기존 고객 도안·저장 결과·자동 배치 엔진을 변경하지 않았습니다.
