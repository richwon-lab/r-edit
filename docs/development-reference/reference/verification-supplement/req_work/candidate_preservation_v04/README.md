# 리치원 후보 보존 독립 시험 v0.4 — 참고 배치

## 실행

압축을 모두 풀고 `experiment.py`를 실행합니다. Python 3.9 이상, 추가 패키지·폰트 설치·인터넷 연결 불필요.

```text
python experiment.py
```

같은 폴더의 `results.json`과 `preview.html`이 갱신됩니다. `preview.html`을 브라우저로 열어 참고 배치와 경고를 확인합니다. 동봉된 결과는 개발 환경에서 미리 실행한 값이며 현재 PC에서 실행하면 갱신됩니다.

## 이번에 검증한 흐름

정상 배치 후보 없음 → 참고 배치 계산 → 위반한 선호 줄 수·기존 커터 기준 표시 → 사람 확인.

정상 자동 배치와 참고 배치를 분리합니다. 참고 배치가 만들어졌다는 이유로 정상으로 바꾸거나 생산 승인하지 않습니다. 실제 커터 지정·원본 디자인·정상 명판의 선택도 바꾸지 않습니다.

## 시험 결과

모든 S/F 문구는 가상 스트레스 시험입니다. 반복된 W나 MONITORING은 긴 문구와 분리 불가능한 문자열을 만들기 위한 것이며 실제 발주가 아닙니다.

| 항목 | 참고 배치 | 확인할 사항 |
|---|---|---|
| S04 | 3.15mm, 4줄, 최소 자폭 약 58.62% | 선호 3줄 초과. 기존 0.3mm 커터 경험 기준은 유지 |
| F05 | 4.3mm, 4줄, 최소 자폭 약 60.52% | 선호 3줄 초과 |
| F06 | 3.2mm, 5줄, 최소 자폭 약 75.01% | 4줄을 임의 상한으로 두지 않음 |
| F07 | 2.5mm, 4줄, 최소 자폭 약 64.57% | 줄 수 초과 + 0.2mm 커터 기준 검토 필요 |
| F08 | 1.95mm, 2줄, 최소 자폭 약 58.12% | 0.1mm 커터 기준 검토 + 등록 자폭 하한 없음 경고 |

S04는 v0.3에서 정상 후보가 없었던 동일 문구입니다. 4줄로 늘리면 홀 회피에 유리한 높이에 긴 줄이 놓이면서 3.15mm로 들어갑니다. 따라서 단순히 3줄 상태에서 글자만 작게 만드는 것과 결과가 다릅니다.

## 참고 배치 선택 방법

1. 정상 배치 검사가 끝나고 후보가 없을 때만 참고 배치를 계산합니다.
2. 선호 줄 수 상한을 풀고 등록된 줄바꿈 위치로 만들 수 있는 조합을 검사합니다. 이번 시험의 줄바꿈 위치는 공백 뒤와 조건에 맞는 마지막 괄호 앞입니다.
3. 4.5mm부터 0.05mm씩 내려가며 배치를 검사합니다. 같은 크기에서 모든 줄 수 조합을 비교한 뒤 하나를 선택합니다.
4. 글자 크기가 최우선입니다. 같은 크기의 후보는 기존 독립 시험의 미관 비용과 고정된 동점 처리로 선택합니다.
5. 원문을 그대로 유지하고, 모든 글자 경계가 지정 영역 안에 있으며 홀 회피 영역과 겹치지 않는지 검사합니다.
6. 참고 배치는 정상 명판끼리의 패턴 점수 비교에 참여하지 않습니다.

단어·식별번호를 임의로 쪼개지 않습니다. 글자 크기는 한 텍스트 영역의 모든 줄에서 같고, 자폭은 줄마다 다를 수 있습니다. 완전한 연속 공간 최적해가 아니라 지정된 줄바꿈 위치와 0.05mm 크기 간격 안에서의 최선입니다.

한 줄 고정 디자인과 사용자가 지정한 전체 줄바꿈은 이번 대상이 아닙니다. 그 제약을 풀어도 된다는 뜻이 아닙니다. 이번 75×25 샘플의 1~3줄은 선호 범위이기 때문에 참고 단계에서만 넘어갑니다.

## 커터 기준

참고 배치 평가에도 기존에 제시한 경험표를 사용합니다. 작은 글자를 0.3mm 커터 정상 후보로 잘못 처리하지 않습니다.

| 글자 크기 | 평가에 쓰는 커터 기준 | 자폭 하한 |
|---|---|---|
| 10mm 이상 | 0.7mm | 56% |
| 5mm 이상 10mm 미만 | 0.5mm | 57% |
| 3mm 이상 5mm 미만 | 0.3mm | 58% |
| 2mm 이상 3mm 미만 | 0.2mm | 64% |
| 2mm 미만 | 0.1mm | 등록값 없음 |

이번 디자인은 4.5mm·0.3mm 커터가 기준입니다. 3mm 미만으로 내려가면 0.2mm 기준의 자폭 하한 64%를 사용하고 경고합니다. 실제 커터를 자동 변경하는 것이 아니라, 사람이 검토할 참고 계산 조건입니다. 위 표는 경험 기준이며 실제 조각 가능성을 보증하지 않습니다.

0.1mm 구간은 사용자가 정한 자폭 하한이 없으므로 새 하한을 임의로 만들지 않았습니다. 반드시 가독성·실제 가공 확인 경고를 표시합니다. 이 구간의 참고 결과를 정상 생산용으로 승인하지 않습니다. 크기 격자의 최저값 0.05mm는 탐색 해상도에 따른 계산 끝점이며 생산 가능 최소 크기를 뜻하지 않습니다.

## 유지한 시험 조건

v0.2/v0.3의 75×25, HY세고딕, 중앙 중심 정렬, 텍스트 영역 (2,2)~(73,23), 기본 자폭 80%, 기준선 간격 ‘글자 크기 + 1.2mm’를 유지했습니다.

홀 중심은 (4,12.5), (71,12.5)mm, 홀 반지름 2mm, 회피 반지름 6mm입니다. 홀과 여백 수치는 이전 시험의 가정이며 고객 확정값이나 회사 공통값으로 정한 것이 아닙니다.

## 검증 항목

- 기존 실발주 9개와 v0.3의 정상·경고 판정 및 선택 결과 유지.
- 참고 배치의 원문·영역·홀 회피·해당 자폭 기준 준수.
- 참고 배치 계산 전후 정상 명판의 전체 선택 데이터 일치.
- 원본 디자인 설정과 기존 커터 지정 유지.
- 후보 열거 순서를 뒤집어도 동일한 참고 배치 선택.
- 5줄 이상을 검토할 수 있고, 실제 5줄 결과가 생성됨.
- 3mm/2mm 등의 커터 구간 경계와 0.2mm 기준 자폭 64% 경계 검사.
- 시험 탐색 한도에 걸리면 ‘탐색 미완료’로 표시. ‘배치 불가능’과 구분.

시험의 탐색 한도는 배치 계산 300,000회입니다. 정상 계산 결과를 빠르게 내기 위해 후보를 임의로 잘라내는 방식이 아니며, 한도에 도달하면 결과를 확정하지 않습니다. 이번 제공 사례는 모두 한도 안에서 완료됩니다.

## 성능과 한계

각 `generation_ms`는 해당 문구의 참고 후보 생성·선택·검증 시간입니다. `total_ms`는 자료 읽기, 기존 회귀 검사, 참고 배치, 순서 반전, 경계 검사까지 포함합니다. Python 시작 시간과 최종 보고서 파일 작성 시간은 제외됩니다.

실제 HY세고딕에서 사전 추출한 문자 경계·advance·윤곽을 사용합니다. 문자열 너비 계산은 실행 시간에 포함되지만 폰트 파일 자체를 읽고 측정하는 시간은 제외됩니다. 대문자 H 높이로 mm를 환산하며 Type3의 크기 정의와 일치는 별도 검증 대상입니다. 충돌은 글자의 경계 상자로 검사합니다.

이번 HTML은 독립 시험 보고서이며 제품 UI나 미관 기준의 확정안이 아닙니다. 영어 언어 처리·자동 패턴 발견·다른 폰트·여러 텍스트 영역·수동 편집·DXF·실제 가공·대량 성능 검증은 포함하지 않습니다.

## 파일

`experiment.py`만 실행하면 됩니다. `baseline_v02.py`와 `v03_experiment.py`는 기존 계산·검증 재사용용입니다. `input.json` 및 `input_v02.json`은 기존 시험 입력, `expected_v02.json`과 `expected_v03.json`은 이전 결과이며 임의로 갱신하지 않습니다. `reference_cases.json`은 이번 가상 문구, `font_metrics.json`은 사전 폰트 측정 자료입니다.
