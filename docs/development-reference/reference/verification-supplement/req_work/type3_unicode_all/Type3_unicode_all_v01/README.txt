Type3 전체 문구 유니코드 표기 시험 v0.1

먼저 할 일
1. 압축을 모두 풉니다.
2. ALL_UNICODE_R2004.dxf를 별도 후처리하지 않고 Type3의 새 빈 파일에 바로 가져옵니다.
3. Expected_layout.png와 비교하고 수정 전 화면을 캡처합니다.
4. 그룹 해제 후 문구가 텍스트로 편집 가능한지 확인합니다.
5. 2004 파일에 문제가 있을 때만 새 빈 파일에서 ALL_UNICODE_R2000.dxf도 비교합니다.

이번 변경
- 기존 L01~L06의 명판 문구 15개와 번호 6개, 총 21개 TEXT를 모두 \U+XXXX로 저장했습니다.
- 문자·숫자·기호·공백을 빠짐없이 변환했습니다.
- 기존의 선택적 후처리 파일이 아닌 원본 Layout 파일에서 만들었습니다.
- 형상·좌표·높이·자폭·폰트·스타일·DXF 버전과 파일 인코딩은 그대로입니다.
- UTF-8로 파일 전체를 변경한 시험이 아닙니다.

확인할 내용
- L01~L06 번호와 전체 문구가 정상적으로 보이는가?
- U가 중간에 있는 문구와 U로 시작하는 UNIT 문구가 모두 정상인가?
- 원래 정상인 U 없는 문구도 계속 정상인가?
- 글자 편집 시 원래 문구로 보이는가? \U+0041 같은 코드 자체가 보이지 않는가?
- 줄바꿈·위치·크기·자폭이 이전 후처리 성공 결과와 같은가?

HY세고딕(H2GTRL.TTF)이 설치된 PC에서 시험합니다. 폰트 파일은 동봉하지 않았습니다.
Expected_layout.png의 홀 주변 색상은 설명용이며 DXF에는 없습니다.
이번 파일에는 베트남어 사례를 추가하지 않았습니다. 기존 6개 사례의 표현 방식만 비교합니다.
파일을 다시 읽어 원문 복원과 다른 데이터의 바이트 단위 보존을 확인했습니다.
Type3에서의 실제 가져오기·편집 성공은 아직 확인하지 않았습니다.
시험용 파일이며 실제 주문·생산용 파일이 아닙니다.
