리치원 자동 배치 — 후보 보존 독립 시험 v0.1
작성일: 2026-10-08

목적
개별 점수가 낮은 후보라도 여러 명판의 패턴을 함께 평가하면 필요할 수 있는지 확인한다.
제품 엔진 구현이 아니라, 후보를 줄이는 방법의 위험을 확인하기 위한 독립 시험이다.

실행
Python 3.10 이상에서 다음 명령을 실행한다. 추가 설치 패키지는 없다.
python experiment.py
같은 폴더에 results.json을 다시 생성한다.

파일
experiment.py: 입력 사례, 비교 계산, 검증 조건, 고정 난수 시험.
results.json: 실행 결과. 대표 사례의 전체 입력 후보와 선택 결과 포함.

범위와 가정
- 후보들은 공간·자폭 하한 등 필요한 조건을 이미 통과했고 같은 우선 글자 크기라고 가정한다.
  실제로 이 조건을 계산하거나 검증한 것은 아니다.
- 글자 측정, 홀 회피, 커터 판단, 영어 해석, 패턴 자동 인식, DXF 출력은 구현하지 않는다.
- 점수 100·95·20 등은 반례를 설명하기 위해 임의로 정했다. 제품 가중치가 아니다.
- 전체 비교란 제공된 후보 목록의 모든 조합이다. 가능한 모든 실제 줄바꿈을 탐색했다는 뜻은 아니다.
- 최종 점수는 개별 점수 합계와 등록된 관계의 일치 보너스로만 구성한다.
- 동점은 고정 ID 순서로 해결한다. 이는 시험 재현용이며 제품의 최종 동점 기준이 아니다.

비교 방식
all: 제공된 모든 후보 조합 비교.
top2: 각 명판의 개별 점수 상위 2개만 남긴 뒤 조합 비교.
signature: 다른 명판과의 평가에 영향을 주는 정보가 완전히 같은 후보끼리만 묶고,
           그중 개별 점수가 높은 후보를 보존한 뒤 조합 비교.
internal_only: 앞뒤 문구가 같은 줄에 붙는지 버리고 내부 줄 구성만으로 묶는 불완전한 방식.

대표 시험 결과
1. NO.1 ABC STOP P/B 와 DEF STOP P/B
   개별 상위 후보는 STOP P/B 앞에 다른 문구가 붙거나 STOP과 P/B가 나뉜다.
   세 번째 후보 NO.1 ABC / STOP P/B를 남겨야 다른 명판과 독립 줄 구성을 맞출 수 있다.
   전체 비교 215점, top2 200점, signature 215점.
   최종 채택: NO.1 ABC / STOP P/B 및 DEF / STOP P/B.
2. E/R AC220V FEEDER PANEL 와 EM'CY AC220V FEEDER PANEL
   FEEDER / PANEL 내부 구성이 같아도 첫 줄 앞에 다른 문구가 붙는지에 따라 관계가 다르다.
   전체 비교 215점, internal_only 200점, signature 215점.
3. 동일 후보에서 두 명판 사이의 관계를 제거
   패턴 일치 보너스가 없어 각자의 개별 최상 후보를 선택한다. 불필요한 묶음 효과 없음.
대표 사례의 원문은 각 후보의 줄들을 공백으로 이었을 때 동일함을 검사했다.

고정 난수 합성 시험
난수 시작값 20261008, 200개 사례, 사례별 4항목·각 6후보.
- signature와 전체 비교의 최종 점수 및 선택 ID 일치: 200/200.
- 항목·후보·관계의 열거 순서 변경 후 동일 결과: 200/200.
- top2의 최종 점수가 전체 비교보다 낮은 사례: 63/200.
- 검사한 조합 합계: 전체 259,200 / signature 9,011.
이는 합성 입력의 구조 검증이다. 현장 오류율·실제 속도 향상률·미관 품질을 뜻하지 않는다.
후보 중복이 포함된 합성 자료이므로 조합 감소율을 실제 발주에 일반화하지 않는다.

설계에 반영할 결론
1. 개별 점수 상위 K개만 남기는 방식은 정확한 보존 기준으로 사용할 수 없다.
2. 패턴 내부 줄바꿈뿐 아니라 앞뒤 문구와 같은 줄을 공유하는지도 평가 관계에 포함해야 한다.
3. 같은 패턴 이름만으로 후보를 합치지 않는다.
4. 모든 외부 평가와 필수 조건에서 동일하게 취급되는 후보 중 열등한 후보만 제거하는 방향을 검토한다.
5. signature가 모든 상호작용을 담는다는 조건 아래에서만 이 시험의 제거 방식이 타당하다.
   향후 위치·크기·다른 패턴·여러 명판 동시 평가 등 새 관계가 생기면 구분 정보와 제거 조건도 재검토해야 한다.
6. 후보가 모두 서로 다른 관계를 가진다면 이 방법으로 거의 줄지 않을 수도 있다.

아직 확인하지 않은 것
실제 문구에서 후보를 만드는 방법, 일반 패턴 인식과 적용 범위, 실제 배치 점수,
글꼴·홀·테두리·자폭·커터 조건, 후보 탐색의 완전성, 수정 후 부분 재계산,
수량·반복 행 처리, 실제 작업 PC의 반응 시간, Type3 가져오기 및 실제 생산 품질.

다음 단계
실제 후보 생성 결과에 대해 묶음 평가가 읽는 정보 목록을 정의하고,
그 정보가 같은 후보를 합쳐도 되는지 소규모 전체 비교로 대조한다.
임의의 후보 개수 제한이나 실제 엔진 전체 구현을 이번 시험으로 확정하지 않는다.
