# 리치원 후보 보존 독립 시험 v0.3

## 실행

압축을 모두 풀고 `experiment.py`를 실행합니다. Python 3.9 이상이며 추가 설치·폰트 설치·인터넷 연결은 필요 없습니다.

```text
python experiment.py
```

실행 파일 옆의 `results.json`과 `preview.html`이 갱신됩니다. `preview.html`을 브라우저로 열면 선택한 배치와 경고를 확인할 수 있습니다. 동봉 결과는 개발 환경의 실행 결과입니다.

## 목적과 통과 조건

글자 크기 축소가 필요한 경우에도 후보 축소 방식이 전체 후보 비교와 같은 결과를 내는지 확인합니다. 별도의 독립 시험이며 실제 제품 엔진 개발이나 기술 선택을 의미하지 않습니다.

1. 정상 배치 후보 중 최대 글자 크기를 먼저 유지한다.
2. 후보를 줄여도 최종 점수와 줄바꿈 선택이 모두 같다.
3. 입력·후보 순서를 바꿔도 결과가 같다.
4. 원문을 보존하고, 영역·홀 회피·자폭 하한을 지킨다.
5. 정상 배치가 불가능한 문구는 경고로 분리하며, 그 문구가 없을 때와 다른 정상 명판의 선택이 같다.
6. 긴 문구가 축소되어도 함께 작업한 짧은 명판의 크기를 같이 줄이지 않는다.
7. v0.2의 실제 문구 9개는 줄바꿈·크기·자폭·좌표·점수를 포함해 이전 선택 결과를 유지한다.

## 시험 입력

실제 발주 9개는 `input_v02.json`, 이전 선택 결과는 `expected_v02.json`에 보존했습니다. 경계 검사용 `S01`~`S04`는 별도로 만든 가상 문구이며 고객이 발주한 문구가 아닙니다.

| 항목 | 확인 목적 | 이번 결과 |
|---|---|---|
| S01 | 기본 크기를 유지하면서 자폭 조정 | 4.5mm, 최소 자폭 약 67.61% |
| S02 | 긴 문구에서 글자 크기 축소 | 3.7mm, 최소 자폭 약 58.44% |
| S03 | 커터 정상 크기 하한에 가까운 경우 | 3.05mm, 최소 자폭 약 58.61% |
| S04 | 정상 배치 후보가 없는 경우 | 확인 필요로 분리 |

S03·S04의 반복된 W는 폭이 긴 분리 불가능한 문자열을 만들기 위한 시험 문자입니다. 실제 고객 약어나 식별번호 규칙을 뜻하지 않습니다. 이런 문자열을 정상적인 발주 사례로 일반화하지 않습니다.

각 가상 문구는 실제 문구 두 개와 함께 비교합니다. 공통 패턴은 시험 입력에서 지정한 `EM'CY STOP P/B`이며 자동 패턴 인식은 구현하지 않았습니다.

별도 수학 시험에서는 정확히 3mm·58%가 허용되고, 사용 가능한 폭을 0.0001mm 줄이면 하한 위반으로 거부되는지 확인합니다. 2.95mm로 줄이면 기하학적으로 들어가더라도 0.3mm 커터의 정상 후보로 받아들이지 않는 것도 검사합니다. 이 별도 시험은 홀 없는 검증용 영역을 사용하며 원래 명판 디자인을 변경하지 않습니다.

## 적용한 조건

v0.2와 동일한 75×25 시험 조건입니다. 디자인 전체의 공통값으로 확정한 것이 아닙니다.

- HY세고딕, 중앙 중심 정렬.
- 4.5mm 우선, 정상 배치 1~3줄.
- 정상 글자 크기 3~4.5mm, 자폭 58~80%.
- 해당 범위는 이번 0.3mm 커터 경험 기준이며 실제 가공 가능성을 보증하지 않습니다.
- 텍스트 영역 (2, 2)~(73, 23)mm.
- 홀 중심 (4, 12.5), (71, 12.5)mm. 홀 반지름 2mm, 회피 반지름 6mm.
- 회피 반지름은 이전 시험의 가정입니다. 고객이 확정한 값이나 전사 공통값이 아닙니다.
- 기준선 간격은 글자 크기 + 1.2mm.
- 크기는 0.05mm 간격으로 검사하며 더 큰 크기에서 후보가 없는지도 다시 확인합니다. 연속적인 크기 전체의 최댓값을 증명하는 것은 아닙니다.

정상 후보를 찾을 수 없다는 판단은 위 탐색 범위 안에서의 결과입니다. 다른 줄 수·디자인·커터로도 제작이 불가능하다는 뜻이 아닙니다.

## 경고 처리 범위

S04는 원문과 경고를 유지한 채 정상 후보 조합에서 제외합니다. S04 추가 전후에 나머지 두 명판의 선택이 같은지 검사합니다. 프로그램에서 정한 자폭 하한을 낮춰서 억지로 통과시키거나, 글자 크기를 3mm 미만으로 낮추고 정상이라고 표시하지 않습니다.

제품에서 필요한 ‘가능한 최선의 참고 배치를 보여주고 사람이 판단하게 하는 기능’은 여전히 요구사항입니다. 이번에는 정상 후보 보존과 예외 분리만 시험하므로 참고 배치는 구현하지 않았습니다. `reference_layout: null`은 기능 제외 결정이 아니라 이 독립 시험의 범위 표시입니다.

## 시간 해석

`generation_and_validation_ms`에는 후보 생성, 경계 검사, 더 큰 크기에서 후보가 없다는 추가 검증이 포함됩니다. 최종 제품의 배치 시간보다 검사 작업이 더 들어 있습니다.

`preserved_selection_ms`는 후보 보존 및 조합 선택 시간입니다. `total_ms`는 파일 읽기, 환경 정보, 이전 9개 회귀 검사, 가상 문구 4개 비교, 순서 변경 검사와 경계 검사를 포함합니다. Python 프로세스 시작과 결과 파일 작성·HTML 생성은 제외됩니다.

폰트는 제공된 HY세고딕에서 미리 측정한 경계·advance·윤곽 자료를 재사용합니다. 런타임 폰트 측정 시간은 포함하지 않습니다. 문자열 너비 계산은 포함됩니다. 대문자 H 높이로 크기를 환산하며 Type3의 크기 정의와 일치는 별도 검증 대상입니다.

## 코드 구성과 한계

- `experiment.py`: v0.3 실행과 경계·회귀 검사, 보고서 생성.
- `baseline_v02.py`: v0.2 계산 코드를 보존하여 재사용. 정상 후보 없음만 별도 예외 형식으로 구분했습니다. 실행 대상은 `experiment.py`입니다.
- `input.json`: 가상 문구 및 이번 시험 조건.
- `input_v02.json`, `expected_v02.json`: 실제 문구와 이전 결과.
- `font_metrics.json`: 기존 폰트 측정 자료. 폰트 파일 자체는 포함하지 않습니다.

다른 명판과의 점수가 패턴 특징에만 의존하는 현재 실험에서 후보 보존의 동등성을 확인합니다. 글자 크기나 자폭을 명판끼리 직접 비교하는 추가 규칙이 들어가면 보존 기준도 다시 검토해야 합니다.

미리보기는 글자 윤곽을 표시하지만 충돌 검사는 경계 상자를 사용합니다. 최종 미관 점수·영어 언어 처리·다른 폰트·여러 텍스트 영역·참고 배치·DXF 출력·실제 가공·수백 개 규모 성능은 이번 시험에 포함하지 않았습니다. 이 결과만으로 제품 엔진의 모든 요구사항이 검증되었다고 판단하지 않습니다.
