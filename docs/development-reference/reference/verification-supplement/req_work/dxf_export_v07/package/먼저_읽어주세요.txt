리치원 DXF 출력 비교 시험 v0.7

이번에는 Python 실행 없이 바로 확인할 수 있습니다.
1. preview.html을 브라우저로 엽니다.
2. Type3의 빈 문서에 01_Quick12_R2000.dxf를 가져옵니다.
3. 먼저 아래 다섯 가지를 확인합니다.
   - HY세고딕으로 정상 표시되는가?
   - 본문은 중앙, NO는 왼쪽 아래, RAT는 오른쪽 아래에 있는가?
   - 미리보기와 줄바꿈·자폭·위아래 위치가 같은가?
   - U가 포함된 문구 등에서 문자가 깨지지 않는가?
   - 그룹 해제 후 각 줄이 편집 가능한 텍스트인가?

파일 구분
- 01_Quick12_R2000.dxf: 정상 99개 중 12개만 추린 빠른 확인용.
- 02_Normal99_R2000.dxf: 정상 99개 전체. 01의 12개를 포함합니다.
  두 파일을 함께 생산하는 것이 아닙니다. 같은 문서에 합쳐 가져오지 마세요.
- 03_Reference_MCB46_R2000.dxf: 검토용 MCB46 1개.
  7줄 / 2.35mm / 기존 0.3mm 커터 크기 기준 미달.
  0.2mm 커터 검토 필요 경고를 유지했으며, 생산 승인 또는 커터 자동 변경이 아닙니다.
- preview.html: 12개와 검토용 1개를 바로 표시. 아래를 펼치면 정상 99개를 봅니다.
- results.json: DXF 재읽기 검사 결과, 명판별 원점과 TEXT 대응표.

배열과 시험 표시
- DXF는 왼쪽 아래에서 오른쪽으로, 다음 줄은 위로 올라갑니다.
- 각 명판 위 R번호/NO는 명판 밖 TEST_NOTES 레이어에 둔 비교용 표기입니다.
- 미리보기 카드는 위에서 아래로 읽되 R번호/NO로 DXF와 대응합니다.
- 파란 텍스트 영역·주황 홀 회피선은 미리보기에만 있습니다.
- 시험 명판은 각각 1개입니다. 실제 주문 수량을 확정한 결과물이 아닙니다.
- 발주 자재·색상·포장 지시 등은 이번 시험에 새로 추정해 넣지 않았습니다.

유지한 내용
- v0.6 결과를 저장한 layout_snapshot.json을 그대로 내보냈습니다.
  줄바꿈을 다시 계산하지 않았고 글자 크기·자폭·기준선·영역도 바꾸지 않았습니다.
- 원본 plate_1753945701427.dxf의 외곽·라운드·홀을 유지했습니다.
- DXF R2000, mm 단위, 한 줄에 TEXT 객체 하나를 사용합니다.
- 문구만 유니코드 이스케이프로 저장하고 폰트 정보는 원래 문자열로 유지합니다.
- 본문 중앙, NO 왼쪽, RAT 오른쪽의 정렬 속성과 계산된 위치를 함께 기록합니다.
- 폰트 파일은 포함하지 않았습니다. HY세고딕이 설치된 작업 PC에서 확인합니다.

확인 범위와 한계
- 원문 공백을 포함한 문자, 크기·자폭·좌표, 좌/중앙/우 정렬점,
  글꼴 메타데이터, 원본 외곽·홀·라운드를 DXF 재읽기로 검사했습니다.
- 미리보기는 저장된 글꼴 외곽으로 그린 예상 모습입니다.
  Type3의 실제 가져오기·글꼴 해석까지 확인한 것은 아닙니다.
- 정상 99개는 v0.6 배치 판정입니다. 이 파일은 전부 시험용이며 생산용이 아닙니다.
- 이번 범위는 36×36 / HY세고딕 / 문구·NO·RAT입니다.
  다른 폰트·디자인의 전체 호환성을 의미하지 않습니다.
- 가공, NC 생성, 글꼴 변경, 새로운 배치 규칙 시험은 포함하지 않았습니다.

필요할 때만 재생성
- 미리 만든 파일 확인에는 설치나 실행이 필요 없습니다.
- 재현하려면 이 폴더에서 다음 순서로 실행합니다.
    python -m pip install -r requirements.txt
    python experiment.py
- 이 시험만 ezdxf 1.4.4를 사용합니다. 제품 구현 언어·엔진 선택은 확정하지 않습니다.
- 입력 파일은 덮어쓰지 않으며 DXF 3개, preview.html, results.json을 다시 만듭니다.
- 출력 시간이 표시되지만 배치 계산·Type3 가져오기 성능 측정값은 아닙니다.
