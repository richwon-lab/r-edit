리치원 저장 결과·DXF 연결시험 v0.1

실행
1. ZIP 전체를 새 폴더에 압축 해제합니다.
2. experiment.py를 실행합니다. 예상 결과: passed 23 / total 23, 정상 종료.
3. preview.html에서 이번 실행의 DXF와 출력 제외 내역을 확인합니다.

추가 패키지
이전 DXF 시험과 같은 ezdxf가 필요합니다. ModuleNotFoundError가 발생하면
실험 폴더에서 현재 사용하는 Python 환경으로 아래 명령을 실행합니다.
    python -m pip install -r requirements.txt
PyCharm에서는 experiment.py를 실행하는 인터프리터에 설치합니다.
동봉된 DXF와 preview.html은 패키지 설치 없이도 열어볼 수 있습니다.

출력 규칙
- 모든 영역이 정상: 정상 명판 DXF.
- 모든 영역에 배치가 있고 참고 결과가 포함됨: 별도 참고 DXF.
- 한 영역이라도 배치가 없음: 명판 전체 제외. 제외 이유는 export_report.json에 기록.
- 정상인 일부 영역만 따로 출력해서 불완전한 명판을 만들지 않습니다.
- 문구 수정·재계산 중에는 기존 결과를 출력하지 않습니다.
- DXF 작성 중 입력이나 채택한 결과가 바뀌면 새 출력 묶음을 확정하지 않습니다.
- 두 번째 파일 작성 실패 시 첫 번째 파일만 완성본으로 남기지 않습니다.
- 기존 출력 폴더에는 덮어쓰지 않습니다.

결과 파일
results.json: 자동 검사 결과.
preview.html: 결과 및 DXF 링크를 정리한 정적 시험 보고서.
DXF/01_Original100/01_Normal_R2000.dxf: 기존 정상 99개.
DXF/01_Original100/02_Reference_R2000.dxf: MCB46 참고 1개.
DXF/02_ExcludedCases/export_report.json: 별도 시험 3개 제외, DXF 없음.
DXF/03_AfterEdit/01_Normal_R2000.dxf: 별도 시험에서 RAT를 10A로 고친 R002 1개.
각 폴더의 export_report.json: 포함 명판, 참고 경고, 제외 명판 및 이유, 출력 검증 내역.
반복 실행 시 DXF_02, DXF_03처럼 새 폴더를 만들며, preview.html은 최신 실행을 가리킵니다.
기존 100개와 별도 수정 시험 1개는 서로 다른 시험 자료입니다. 합쳐서 생산하지 않습니다.

변경 범위
result_state_v01의 저장 자료와 계산·상태 코드는 그대로 복사했습니다.
integration_v010의 exporter_v07.py도 변경 없이 사용합니다.
result_export.py만 상태별 분류, 제외 내역, 출력 직전 검증을 연결합니다.
experiment.py는 저장 결과로 실제 DXF를 생성하고 다시 읽어 검증합니다.
배치 엔진을 불러오거나 후보를 재탐색하지 않습니다.
출력된 100개 명판의 300개 영역과 439개 TEXT를 저장 결과와 대조합니다.

유지한 사항
- 기존 R2000 형식, 편집 가능한 TEXT, 글꼴 메타데이터.
- 문구의 공백·구두점·대소문자, 줄바꿈, 위치, 크기, 자폭.
- MCB46 참고 결과의 원래 0.3mm 공구 기준 및 기존 경고.
- 글자 내부나 공백에 홀을 끼워 넣지 않는 기존 줄 사각 범위 배치.

제한
기존 출력기의 시험 대상인 36×36mm, 홀 2개 도형에 한정합니다.
기존 DXF 시험용 표기(V0.10 포함)를 그대로 유지했습니다.
6개 홀 등 새 도형의 DXF 출력 지원이나 새로운 배치 정책은 추가하지 않았습니다.
Type3에서 새로 확인한 결과가 아니며, 파일 생성은 생산 승인을 뜻하지 않습니다.
로컬 단일 작업의 출력 묶음 확정 시험입니다. 클라우드 동시 저장이나 정전 복구는 포함하지 않습니다.
입력 저장본의 체크섬은 우발적 변경 검출용이며 보안 서명이 아닙니다.
