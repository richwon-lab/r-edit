리치원 배치·공간검사 분리시험 v0.1

실행
1. 압축을 모두 풀고 preview.html을 브라우저에서 열면 생성된 결과를 봅니다.
2. 재실행: Python 3.10 이상으로 experiment.py 실행. 외부 패키지는 필요 없습니다.
3. results.json / layouts.json / preview.html은 실행 파일 옆에 다시 생성됩니다.
4. 모든 검사 통과 시 종료 코드 0, 검사 실패 시 1입니다.

이번에 변경한 부분
- 기존 Python 통합시험을 복사해 RegionProbe.fit의 계산과 검사를 분리했습니다.
- placement_split.py의 propose_layout: 기존 방식으로 위치·자폭을 계산합니다.
- inspect_proposal: 배치를 변경하지 않고 줄 사각 범위를 검사합니다.
- RegionProbe.fit_detailed: 제안 결과와 검사 결과를 함께 돌려줍니다.
- 기존 엔진이 호출하는 fit: 통과한 경우에만 기존과 같은 줄 목록을 반환합니다.
- 탈락·판정 불가의 상세 결과에는 원문의 문자 위치, 줄 번호, 관련 조건을 남깁니다.
  문자 위치는 원문 문자열의 0부터 시작하는 [시작, 끝) 인덱스입니다.
  홀 식별값은 현재 시험 디자인의 holes 배열 인덱스입니다.

검증
- 저장된 실제 발주 100행의 본문·NO·RAT 총 300영역 전체 결과를 정확히 비교합니다.
- 정상 99행, 참고 1행(MCB46: 7줄·2.35mm), 문구·좌표·자폭·크기·경고가 유지됩니다.
- 기존 fit과 분리 후의 제안 결과도 모든 300영역에서 비교합니다.
- 검사기는 제안을 변경하지 않아야 하며 반복 검사 결과가 같아야 합니다.
- 시험용으로 3mm 후보를 탈락시켰을 때 2.95mm까지 탐색하는지 확인합니다.
- 입력 스냅샷과 원래 참조 코드의 해시를 확인합니다.

현재 한계
- 홀로 인한 보수적인 사각 범위 자폭 제한은 여전히 제안 단계에 남아 있습니다.
  실제 글자의 빈 부분을 검사해 더 넓은 자폭을 허용하는 개선은 아직 아닙니다.
- 기존 1e-9/1e-8 수치 허용값을 유지했습니다. 제품용 오차 기준 확정은 아닙니다.
- 검사 대상은 줄 사각 범위·텍스트 영역·원형 홀입니다.
  실제 글자 윤곽, 둥근 외곽, 테두리·장식, 회전은 이번 구현 범위에 포함하지 않습니다.
- 원문 위치도 현재는 줄 범위입니다. 정확한 글리프별 침범 위치는 아직 제공하지 않습니다.
- fit_detailed에서 상세 이유를 제공합니다. 기존 배치 엔진의 fit 반환 형식은 유지했으며,
  전체 발주의 최종 오류 집계·UI·후보/디자인 버전 연결은 이번에 구현하지 않았습니다.
- 기존 제품 엔진·고객 정책·출력 파일은 변경하지 않았습니다. DXF를 새로 생성하지 않습니다.
- 기존 측정값과 경로를 사용합니다. Type3의 외곽과 정밀하게 일치하는지 확인한 시험은 아닙니다.
- saved_job_r1.json은 읽기 전용 비교 입력입니다. 이 시험은 저장·재개·출력용 버전을 갱신하지 않습니다.

파일
experiment.py: 실행과 검증, 결과 생성
placement_split.py: 배치 제안·검사 분리
regions_v05.py: 분리한 함수를 연결한 통합시험 복사본
legacy_regions_v05.py: 변경 전 직접 비교 기준
engine_v06.py / baseline_v02.py: 기존 시험 코드 그대로
saved_job_r1.json / source_manifest.json: 기존 저장 결과와 출처 해시
results.json / layouts.json / preview.html: 생성 결과

공유 실험 자료이며 완성된 제품 엔진이나 생산 승인 결과가 아닙니다.
