리치원 결과·실패 이유 저장 연결시험 v0.1

실행
1. ZIP을 새 폴더에 모두 압축 해제합니다.
2. experiment.py를 실행합니다. Python 표준 라이브러리만 사용합니다.
3. passed: 30 / total: 30, 정상 종료를 확인합니다.
4. preview.html을 열면 수정 전후의 현재 결과 제공 여부를 볼 수 있습니다.

검사 범위
- 기존 100행·300영역의 배치, 정상 99행·참고 1행, MCB46 경고 보존.
- 저장된 상태·검사 이유·원문 위치·탐색 단계 내역의 정확한 복원.
- 별도 Python 프로세스에서 배치 엔진을 불러오거나 재계산하지 않고 열기.
- 문구 수정·계산 중·계산 오류·취소 후에는 과거 결과를 현재 결과로 제공하지 않음.
- 수정 전 계산이 늦게 완료돼도 과거 결과를 다시 채택하지 않음.
- 문구를 고쳐 재계산하면 새 결과와 새 검사 내역으로 교체.
- 현재 입력에 맞지 않는 결과는 현재 결과로 저장하거나 출력 준비할 수 없음.
- 결과와 입력·탐색 한도의 연결, 엔진 및 글꼴 측정 자료의 재계산 검증.
- 파일 교체 직전 중단 시 기존 저장 파일 보존.

생성 파일
results.json: 검사 결과.
preview.html: 상태 전환 기록을 보여주는 정적 시험 보고서.
state_transitions.json: 수정 및 계산 단계별 현재 결과 제공 여부.
saved_with_reasons.json: 기존 100행 결과와 실패 이유를 담은 별도 저장본.
saved_diagnostic_cases.json: 계산 불가·배치 없음·탐색 미완료의 별도 3행 시험본.
saved_after_edit.json: 위 시험본에서 RAT 측정 불가 문자를 제거하고 재계산한 저장본.
saved_job_r1.json: 수정하지 않는 기존 원본 시험 자료.
source_manifest.json: 복사한 기준 파일 및 변경 파일 목록.

예시 문구 변경은 별도 시험 입력에만 적용합니다. 실제 발주 문구를 수정하지 않습니다.
각 재실행은 이 폴더의 생성 파일을 갱신합니다. 원본 saved_job_r1.json은 변경하지 않습니다.

구현 범위
result_reasons_v01의 배치·검사·이유 집계 코드를 그대로 사용합니다.
기존 snapshot_v08.py와 state_probe.py의 저장·현재 결과 관리 흐름에 연결했습니다.
새 시험 엔진의 파일 식별값을 기록하며, 예전 저장 결과를 새 엔진 결과로 바꿔 부르지 않습니다.
start_trial은 별도 시험 개정을 시작하고, 재계산을 끝낸 결과만 저장합니다.
result_store.py가 저장 결과와 입력의 연결 및 표시 상태의 일관성을 확인합니다.
현재 화면용 접근은 Session.current_results()를 사용합니다. 계산 전 결과는 None입니다.
Session.accepted에는 이전 계산이 내부적으로 남을 수 있으므로 현재 결과 표시용으로 직접 쓰지 않습니다.
이 실험에서는 문서 단위로 무효화합니다. 영역별 부분 재계산이나 제품 UI의 표시 방식은 구현하지 않았습니다.

제한
완료된 계산 결과의 저장만 다룹니다. 미완료 편집의 임시 저장·복원은 포함하지 않습니다.
계산 완료 상태와 생산 승인 상태는 다릅니다. 참고 결과나 계산 불가도 진단 기록으로 저장됩니다.
검사 내역은 실제 검사한 후보만 포함하며, 가지치기된 모든 후보의 실패 원인을 뜻하지 않습니다.
내부 체크섬은 우발적 변경 및 연결 오류를 검출하기 위한 것으로 보안 서명이 아닙니다.
로컬 단일 작업 시험이며 제품 적용, 클라우드 동시 저장, DXF 생성, Type3 확인은 포함하지 않습니다.
줄 전체 사각 범위와 지정 홀 여유를 유지하며, 글자 내부·공백에 홀을 끼워 넣는 기능은 없습니다.
실행 시간은 검증용 재계산과 저장 시험을 포함하므로 제품 성능 수치가 아닙니다.
